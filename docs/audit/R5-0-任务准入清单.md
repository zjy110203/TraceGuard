## 2. R5-1 具体开发任务（准入后执行）

按依赖顺序排列。每项都给出命令、验收证据与"不得做什么"。

### R5-1-A 干净环境四门禁复验（第一优先）

- 命令（在 `D:/桌面/TraceGuard/traceguard` 下）：
  - `.venv/Scripts/python.exe -m ruff check .`
  - `.venv/Scripts/python.exe -m ruff format --check .`
  - `.venv/Scripts/python.exe -m mypy packages apps --ignore-missing-imports`
  - `mkdir -p .traceguard-tmp/r5/pytest && .venv/Scripts/python.exe -m pytest -q --basetemp=.traceguard-tmp/r5/pytest`（注意 `set -o pipefail`，禁止用 `tee` 吞退出码）
- 验收：四项退出码均为 0；pytest 数量 ≥333；日志落在 `.traceguard-tmp/r5/`；记录耗时与环境。
- 禁止：删除失败测试、改断言、`--basetemp` 指向业务 `data/`、扩大 `docs/research` 排除范围。
- 若失败：定位真实根因（R4 已有"jsonschema 缺失""tee 吞码""宿主 shim SystemExit"三类先例），不得靠放宽规则通过。

### R5-1-B 前端构建与类型检查复验

- 命令：`cd apps/web && npm ci && npm run build && npx vue-tsc --noEmit`。
- 验收：三条退出码 0；`dist/` 产物存在且由真实源码生成；记录 Node/npm 版本。
- 注意：`npm ci` 会重建 `node_modules`，属依赖操作，必须在 R5-1 准入后进行；不得全局安装依赖。

### R5-1-C 浏览器 E2E 基线复验（含分辨率补缺）

- 命令：先 `python -m scripts.serve`（只绑定 127.0.0.1，记录 PID/端口），再 `python -m scripts.ui_acceptance.py`。
- 验收：全部核心页面真实加载；console.error 与 ≥400 的 `/api/` 响应为 0；
  **补测 1920×1080 与 768px**（R4 只测了 1440×900 / 1024×768 / 390×844）。
- 禁止：把 R4 的 65/65 直接当作本阶段证据；不得用 mock 服务替代真实 FastAPI。
- 收尾：只停止本任务自己启动的 serve 进程，确认 PID 归属。

### R5-1-D CI 门禁补全方案（先论证，后实施）

- 现状：CI 只有 ruff / format / mypy / pytest；无前端构建、类型检查、浏览器 E2E、安全专项。
- 任务：先产出方案说明（必要性、执行时长、失败可诊断性、是否分 job），
  **经批准后**才修改 `.github/workflows/ci.yml`。
- 验收：方案中每条新增门禁都有明确命令与阻断规则；不删现有门禁；保留 pipefail 与失败 artifact。
- 禁止：未经批准改 CI；用 `--ignore` / `continue-on-error` 掩盖失败。

### R5-1-E 统一验证入口

- 目标：一个命令跑完全部门禁，并保留真实退出码与留档。
- 约束：不得 Mock；测试用独立目录、独立 DB、独立浏览器上下文；
  脚本必须在任何一步失败时以非 0 退出，并把命令/退出码/数量写入 `.traceguard-tmp/r5/verify.log`。
- 验收：连续两次执行结果一致；故意注入一个失败用例能正确阻断（可用临时副本，不污染真实测试）。
