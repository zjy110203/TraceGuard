## 4. 本轮发现并修复的真实缺陷

均由**几何测量**或**截图审阅**定位，非猜测：

1. **顶栏面包屑溢出**：`.crumbs` 高 70px、`y=-10`，溢出 52px 顶栏。
   根因：`App.vue` 中裸 `nav {flex-direction:column}` 误命中面包屑 `<nav>`。
2. **移动端标题竖排**：PageHeader 标题列缺 `min-width:0`。
3. **移动端标题下 260px 空白**：列方向 flex 中 `flex-basis:260px` 变成高度。
4. **表格窄屏被裁切**（16 个视图）：缺滚动容器；已统一包裹 `.table-wrap`。
5. **Intents 表单固定 4 列**最小 ~500px，390 下溢出。
6. **轨迹哈希撑破版面**：`.truncate` 的 `nowrap` 阻止换行。
7. **System `[object Object]`**：嵌套对象直接 `String()`。
8. **Overview 全站 console 404**：浏览器探测 `/favicon.ico`；补品牌图标 + API 204 吸收。

## 5. 仍然存在的已知限制（不掩饰）

- `/graph` 采用单环布局（非力导向），节点数 >40 时环上间距不足，需要分簇或分层布局；邻接查询已支持 `limit/offset` 分页，但前端仍按 200 条上限取用，未做「加载更多」。
- `/benchmark` 在 GT 未批准时只能展示空态与 NOT_RUN；这是**正确行为**，不是缺陷。
- `/diagnosis` 的置信度为后端返回值，前端未做多假设概率重算。
- `/repairs` 依赖后端提供的 diff 文本，未做行内语法高亮。
- 深色模式下的图表色板已适配，但打印（print）样式未专门处理。
