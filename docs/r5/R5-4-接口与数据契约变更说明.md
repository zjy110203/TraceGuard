# R5-4 接口与数据契约变更说明（增量）

本文档是 `docs/design/05-统一契约与模块接口设计.md` 的 R5-4 收口增量，只列变化项。
基线：`c6e2efb`；实施：R5-4.6 / R5-4.7 / R5-4.8（未提交工作区）。

## 1. REST 接口变化

### POST /api/v1/explorations
- 请求新增字段：`scenario: str = "teamflow-login"`、`goal`、`expected_outcomes: list[str]`、`target`、`required_assertions: list[str]`、`constraints: list[str]`（R5-4.1 已声明，本轮起**全量持久化并入 Trace 哈希**）。
- `policy` 取值扩展：`scripted` | `scripted-agent`（`llm` 仍 409）。
- `scenario` 未注册 → **422**，`error.details.code = "UNSUPPORTED_SCENARIO"`。
- `target` 不再回退为 `base_url`：未声明即视为未声明。
- 响应新增：`goal_status`（VERIFIED/NOT_VERIFIED/INCONCLUSIVE/NOT_EVALUATED）、`goal_reason`、`goal_checks[]`、`hash_version`。

### GET /api/v1/explorations、GET /api/v1/explorations/{id}
- 列表/详情新增 `goal_status`、`goal_reason`；详情含完整 `test_intent`（含 `scenario`）。
- 详情读取时仍会重算 `trace_integrity_verified`（v1/v2 按 `hash_version` 选择公式）。

### POST /api/v1/explorations/{id}/compile
- 准入链（任一失败拒绝）：status=COMPLETED → 有已接受动作 → **Trace 完整性验证** → 目标重算 == VERIFIED（且与记录值一致）→ Compiler。
- 拒绝时 409/422，`details` 携带 `goal_status`、`reason`、逐条 `checks`（name/expected/observed/evidence/deferred）。

### POST /api/v1/candidates/{id}/approve
- 请求体新增**必检**字段：`review_confirmed: list[str]`（必须覆盖全部 `required` checklist id）、`uncertainty_acknowledged: bool`（存在不确定项时必须为 true）。
- 违反 → 422，`details.missing_confirmations` / `details.uncertainty_count`。
- 服务端在批准前重新执行：溯源验证（exploration 完整性 + hash 一致性 + 目标重算）与 Compiler 静态校验。
- 响应/记录新增：`review_confirmed`、`uncertainty_acknowledged`、`reviewer_is_local_audit_field: true`。

### POST /api/v1/candidates/{id}/reject
- `reason` 变为必填（422 if empty）。

### GET /api/v1/candidates、/candidates/{id}
- 列表新增 `goal_status`；摘要 `oracle_sources[]` 新增 `expected_value`。
- `review_checklist` 由 `string[]` 变为 `{id, text, required}[]`（旧字符串记录读取时自动转换）。
- 详情新增 `data_refs`（value 恒空或非敏感 fixture）、`observations`、`goal_checks`、`goal_reason`。

### POST /api/v1/chains（摘要/记录）
- 摘要与记录新增三个独立状态轴：`persistence_status`（OK/PARTIAL/FAILED）、`graph_status`（OK/PARTIAL）、`chain_status`（聚合：FAILED 支配 PARTIAL）。
- `persisted.evidence.failures[]` 可能出现 `outcome=RETAINED_FOR_RECOVERY`（截图字节保留于报告）。
- Run 行为：执行成功但持久化失败时 Run 仍为 COMPLETED（执行轴），失败信息在 run report `persisted` 与 chain 记录中可查。

## 2. 数据模型变化

### ExplorationTrace（packages/agents/exploration.py）
- 新字段：`test_intent: dict`（入哈希）、`hash_version: int = 2`、`goal_status/goal_checks/goal_reason`（派生态，**不入哈希**）。
- 哈希 v2 范围：exploration_id、test_intent、action_sequence、observations、agent_decisions、security_events、stop_reason、agent/prompt/tool/application/browser 版本；`hash_scope` 字段固定词表。无 `hash_version` 的历史记录按 v1 验证。

### StopReason
- 移除 `GOAL_REACHED`；新增 `PLAN_EXHAUSTED`（计划耗尽）与 `GOAL_VERIFIED`（计划耗尽且目标评估通过）。
- 新增类：`ExplorationStatus`（COMPLETED/FAILED/CANCELLED）、`GoalStatus`、`evaluate_goal()`、`GoalCheck/GoalEvaluation`。

### CandidateTestCase（packages/agents/compiler.py，COMPILER_VERSION=1.2.0）
- `review_checklist: tuple[dict]`（id/text/required）；
- 新字段：`goal_status/goal_checks/goal_reason`；
- 编译准入：goal 必须 VERIFIED；url 断言只来自 `intent.target`（观察路径回退已删除）。

### TestCaseVersion.validate()（新增规则）
- 敏感 TestDataRef（ref_id 命中 pass/secret/token/api_key/credential）携带内联 value → 拒绝。

### EvidenceManager.import_record
- 幂等语义内容感知：同 id 且 integrity_check 不同 → `ValidationError`（分类 FAILED，非 DUPLICATE）。
- 成功导入时把 `blob{key,size,sha256}`/`byte_length`/`binary_sha256` 回写调用方 record；hex `image` 字节由调用方条件剥离。

### BrowserManager / PlaywrightAdapter
- 共用 `OriginPolicy`（packages/execution/netpolicy.py）：精确 origin + 主机名白名单；页内 scheme 放行；userinfo 拒绝。
- BrowserManager 新增：route 全量拦截、popup 关闭、download 取消、ws 关闭、最终 URL 检查、`security_evidence()`。
- 浏览器通道统一 `browser_channel()`：`TRACEGUARD_BROWSER_CHANNEL` 环境变量（空 = 内置 Chromium）。

## 3. 前端契约（apps/web）

- `ExplorerView`：完整 TestIntent 表单；执行状态/停止原因/目标验证三轴展示；goal checks 列表；编译按钮 gate 于 `goal_status === 'VERIFIED'`。
- `CandidatesView`：审核依据 14 项展示 + 逐项 checklist 确认 + 不确定项确认；批准按钮 gate 于全部确认；approve 请求携带 `review_confirmed`/`uncertainty_acknowledged`；退回必填理由。
- `CaseDetailView`：执行全链按钮增加 `data-testid="run-chain"`。
- 新增 E2E 定位属性（视觉冻结约束下的最小增量）：`exp-intent-ref`、`exp-scenario`、`exp-goal`、`exp-outcomes`、`exp-target-path`、`exp-required-assertions`、`exp-constraints`、`exp-policy`、`exp-base-url`、`goal-status`、`goal-checks`、`stop-reason`、`compile-candidate`、`open-candidate`、`candidate-intent`、`candidate-goal-checks`、`candidate-step`、`candidate-oracles`、`review-checklist`、`checklist-<id>`、`uncertainty-ack`、`approve-candidate`、`reject-candidate`、`reviewer`、`approval-record`、`reject-reason`、`run-chain`。

## 4. 兼容性

- 历史 Exploration / Candidate / Case 文件读取能力保持：v1 哈希兼容验证、旧 checklist 字符串自动结构化、旧 intent 字段缺省为空。
- TestCaseVersion append-only 约束不变；正式库无 schema 变更。
- 破坏性变化仅一处：`StopReason.GOAL_REACHED` 消失（消费方为展示层，已同步）。
