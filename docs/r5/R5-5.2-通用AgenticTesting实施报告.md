## 3. 场景契约（§14）

`Scenario` 的字段与要求一一对应：`scenario_id / name / description / allowed_origins / initial_url /
intent_templates / goal_definition / allowed_actions / constraints / success_conditions / stop_conditions /
timeout_budget_s / evidence_requirements`（外加 `steps / max_steps / implemented / blocked_reason`）。

`validate()` 拒绝：

- 非法 id、空名称/描述/入口；
- 空 `allowed_origins` 或不是 `scheme://host[:port]`；
- 空 `goal_definition`，或断言定义不合法（未知 kind、缺 value/testid、正则不编译）；
- 空 `allowed_actions`、包含网关不认识的工具、缺 `navigate`/`snapshot`；
- **空 `constraints`**（没有边界的场景不允许注册）；
- 缺成功条件/停止条件、预算 ≤ 0、空取证要求；
- 已实现但 `steps` 为空，或步骤用了 `allowed_actions` 之外的工具。

重复注册直接报错（不静默覆盖）。

## 4. 目标断言（§15）

| 类型 | kind | 说明 |
|---|---|---|
| URL 精确 | `url_exact` | 与 `url_path` 比较 |
| URL 正则 | `url_regex` | 定义期编译校验 |
| 元素存在 | `element_exists` | 依 `visible_elements` |
| 元素可见 | `element_visible` | 依 `visible` 标志；旧观测无此字段 → INCONCLUSIVE |
| 元素文本 | `element_text` | 依 `name`（≤60 字有界标签，**不是** innerText 全量，报告如实标注） |
| testid | `testid` | 依 `visible_testids` |
| 表单状态 | `form_state` | present/absent/visible/disabled；**从不读输入值** |
| 页面状态 | `page_state` | title / url_path / text 包含 |
| 组合 | `all_of` / `any_of` / `not` | 逐层归并：FAILED 优先于 INCONCLUSIVE |
| 必要/可选 | `required: true/false` | 可选失败只记录，不否决 |

语义（与 §15 的要求逐条对应）：

- 每项有独立 verdict、expected/observed、**evidence 路径**；
- 观测不可用（无 DOM 采样）→ `INCONCLUSIVE`，永不 `FAILED`；
- 只有可选断言的 goal → `INCONCLUSIVE`（"通过"证明不了任何事）；
- 必需断言失败 → `NOT_VERIFIED`；必需断言不可观测 → `INCONCLUSIVE`；
- 断言失败时，**即使原 goal 评估是 VERIFIED 也会被收紧**为 NOT_VERIFIED/INCONCLUSIVE（只收紧、不放宽），
  因此 Compiler 准入语义没被削弱；
- 断言在读取时**重新计算**并比对（`goal_assertions_verified`），不把派生结果当原始事实。

## 7. 已知限制

1. 场景仍由 ScriptedProvider 驱动：**决策序列是场景数据，不是模型推理**。这是 D8 的边界，报告不越界表述。
2. 每个场景的"正常/失败/边界/恢复"四类用例只对两个场景做全（登录、创建），查询/导航只做到注册与脚本；
   边界（如名称超长 200 字符）与错误恢复（网络中断）未覆盖。
3. `element_text` 基于有界标签而非完整 innerText；复杂断言（如表格行数）需要观测层再扩展。
4. `{unique_suffix}` 是刻意引入的可重复性机制，不属于业务语义。
5. 场景 `allowed_origins` 写的是默认端口 8001；换端口时由请求的 `base_url` 覆盖（`Budget.allowed_origins` 用真实 origin）。
6. **`intent_templates` 不自动注入请求**：一旦注入，"无目标"的探索会凭空获得 target，
   R5-4.6 的 `NOT_EVALUATED` 语义就永远不可能出现（本轮 e2e 已复现该回归并修复）。
   模板通过 `GET /explorations/policies` 暴露，由调用方（UI）显式带入。
