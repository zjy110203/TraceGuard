## 0. 怎么用这张单

1. 责任人只填自己那一行的"结论 / 日期 / 签字"三格，**不要改动推荐方案列**（推荐是研发侧的技术判断，改动会让审计看不到原始建议）。
2. 结论只有四种合法取值：`批准` / `不批准` / `延期至 <日期>` / `改采 <方案编号>`。
3. **"延期"必须给出日期**。无日期的延期等价于"不批准"，且会让下游阶段无限期阻塞——这是本单刻意设计的严格性。
4. 每一行都标注了"未决策的后果"。请先读后果再决策，避免以为"不表态就是保持现状"。
5. **15 行需批准项**全部落定后（N2/N4/N7 三行为 `REGISTERED`，不计入），由项目负责人在 §9 汇总签"同意冻结"，`M0_FROZEN` 才可置 `true`。

**状态图例**：`PENDING`（未决，需批准）/ `APPROVED`（已批准）/ `REJECTED`（不批准）/ `DEFERRED`（延期，须带日期）/ `REGISTERED`（已登记为必修项，无需批准）。

> **为什么区分 `PENDING` 与 `REGISTERED`**：本单里混了两类事项——一类需要"人点头"（决策、风险接受），一类只需"有人去做"（N2/N4/N7 是纯缺陷修复，按工程纪律直接修，没有需要批准的选项）。把后者也标 `PENDING` 会让它们永远等一个**不需要的签名**，从而虚假地阻塞 M0 冻结。因此 N2/N4/N7 标 `REGISTERED`：不计入冻结条件，但必须出现在 M1 交付里。
