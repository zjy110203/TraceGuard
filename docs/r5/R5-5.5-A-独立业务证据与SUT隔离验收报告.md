# R5-5.5 A：独立业务证据与 SUT 隔离验收

状态：**本机实现与验收通过**。TeamFlow 的业务数据仍使用共享 `DATABASE_URL` 作为生产默认；只有显式配置 `TEAMFLOW_DATABASE_URL` 时才使用独立库。本报告的独立数据库测试是明确配置的测试拓扑，不改变生产默认。

## 实施内容

- TeamFlow Eval API 提供运行级种子、业务状态快照和清理端点。端点要求 `X-Eval-Token`，项目名、ID、描述 owner marker 与 run ID 相互校验；重复相同种子可复用，身份冲突和跨 run 清理返回冲突。
- Explorer 通过 SUT 的公开业务状态端点独立读取 TeamFlow 实际项目状态，在 setup 前后、动作后、动作结束和 cleanup 后记录摘要、状态哈希及差异。Eval token 不写入探索记录或浏览器输入。
- 状态源不可用或格式不符时记录 `UNAVAILABLE` 并将证据判为 `INCONCLUSIVE`；这不会覆盖既有 Test Verdict、Oracle 或 Trace。清理失败会留下 `CLEANUP_FAILED` 以供恢复，不伪报清理成功。
- 仅对具备本次 run 双重 owner 标记的资源执行 cleanup。业务断言只由公开业务状态支持；审计结论范围限于证据是否可用和本次 run 资源是否清理。
- 独立 TeamFlow 数据库只创建 TeamFlow / Eval 自有表。Repair Sandbox 子进程把 `DATABASE_URL`、`TEAMFLOW_DATABASE_URL` 和兼容变量全部指向每次沙箱的临时库，避免在共享或显式分库拓扑下写入 Platform / 正式 SUT 数据库。

## 验收证据

- 2.1.0 仍是显式 opt-in；六个场景各执行 normal、exception、boundary、recovery 四条真实 Chromium 路径，共 24 条路径。测试以独立 `qa_runner` 用户和 TeamFlow SQLite 状态核验创建 / 更新 / 未创建的业务结果，并验证每条路径 cleanup、owner 隔离、trace hash、无 token 泄露，以及负向路径编译返回 409。
- Explorer 与 TeamFlow Stage 1/API 专项：42 passed（包含服务不可用和错误业务状态源负向用例）。
- 手工 Repair 完整闭环与分库恢复综合验收：1 passed，93.25 秒。失败 Run、支持的 Diagnosis、人工 Locator 修改、人工审批、隔离 Sandbox、Promotion、进程重启、回归、Rollback、二次重启及旧版本预期失败均通过。

详细的手工闭环及分库恢复结果见 [manual-repair-closed-loop.json](evidence/r5-5.5/manual-repair-closed-loop.json) 和 [separate-database-restore-check.json](evidence/r5-5.5/separate-database-restore-check.json)。归档文件路径已去除本机临时目录；摘要见同目录 `manifest.json`。

## 边界

本验收证明当前单机 SQLite、单进程与真实 Chromium 拓扑中的业务证据闭环。它不证明跨多进程分布式锁、正式生产数据库在线快照或多个外部 SUT 的身份管理。`project-edit` 与 `form-validation` 虽然在本轮 opt-in 新版本中有真实路径执行，但其长期数据目录、编辑路由成熟度及跨版本维护仍需后续治理。
