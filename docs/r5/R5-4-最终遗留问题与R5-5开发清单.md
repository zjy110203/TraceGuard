## 2. 本轮新产生的遗留问题（按优先级）

| # | 问题 | 影响 | 建议归属 |
| --- | --- | --- | --- |
| L1 | `scripted-agent` 的决策序列仍由部署编排（`teamflow_login_agent_steps`），场景仅 teamflow-login 一个 | 新业务场景需人工编写决策脚本 | R5-5：真实 LLM 接入后由模型驱动 |
| L2 | reviewer 为本地审计字段，无身份认证 | 审批记录不可作为安全凭据（记录中已显式标注） | R5-5+：身份模块 |
| L3 | 单个 Playwright 动作阻塞期间取消无法即时生效（sync API 限制），由动作超时（max_action_s）兜底 | 取消延迟上限 = 单动作超时 | R5-5：评估复用 Dispatcher 做驱动级取消 |
| L4 | `S3BlobStore` 未实现（构造即拒绝），仅 LocalBlobStore 可用 | 对象存储部署形态不可用 | 后续部署阶段 |
| L5 | Evidence 重复 ID 判定基于 integrity_check，不比对 payload 全文 | 理论上同 hash 不同 payload 的碰撞不可检出（SHA-256 前提下可忽略） | 记录在案 |
| L6 | Trace Hash v2 只覆盖新探索；更早的历史轨迹仍是 v1（intent/decisions 不在哈希内） | 历史轨迹的 intent 篡改不可检出（v1 兼容的代价） | 记录在案 |
| L7 | `evaluate_goal` 的 expected_outcomes 文本比对基于最终观察的 text_excerpt（3000 字符截断） | 超长页面上靠后的预期文本可能观察不到 → INCONCLUSIVE/NOT_VERIFIED | R5-5：按元素级断言扩展 |
| L8 | workbench UI 的 SSE 断线重连在 explorer 长任务期间未做 UI 层演示 | 不影响正确性 | 低优先级 |

## 3. R5-5 开发清单（建议顺序）

1. **真实 LLM 接入（D8）**：`provider_from_env` 已就绪（DeepSeek/OpenAI 兼容）；需要：密钥管理、费用预算闸、真实推理标记翻转（`may_contain_real_inference`）、Explorer API 的 `llm` 策略解禁、决策环压测。
2. **场景扩展框架**：把 `SUPPORTED_SCENARIOS` 从单登录场景扩为可注册场景包（意图模板 + 起始决策 + 目标验证配置），配合真实 LLM 后由模型接管决策。
3. **目标评估增强**：元素级（testid/text/URL 正则）预期结果语法，替代纯 text_excerpt 包含判断（解决 L7）。
4. **身份与审批**：最小身份模块（本地账号 + 审批签名），让 reviewer 从审计字段升级为可验证身份（解决 L2）。
5. **驱动级取消/超时**：Playwright async API 或子进程隔离，实现动作中取消（解决 L3）。
6. **对象存储适配**：S3BlobStore 实现 + 一致性测试（解决 L4）。
7. **Benchmark 正式评估**：UI-FaultBench 准确率跑批与报告。
8. **Repair 自动执行**：修复沙箱 → 提案 → 人工批准 → 版本晋升的完整闭环（当前只到提案）。
