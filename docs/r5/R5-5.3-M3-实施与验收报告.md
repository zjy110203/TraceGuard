# R5-5.3 M3 实施与验收报告

日期：2026-11-26
运行模式：Scripted / Mock；本阶段没有调用真实模型。

> 当前增量状态：本报告中的 CI/Python 数量是历史快照。F4 已把 Mock Agent、ExecutionAuthorization、SecretResolver 与 PostAction 接入真实 Explorer API；F5 为 Trace v3 增加场景身份字段。当前证据见 [F1–F7 补充状态](R5-5.3-F1-F7-实施补充与验收状态.md)。

## 交付内容

- `context_builder.py` 确定性构造有界上下文，安全约束不随普通内容截断。
- Planner 只产生结构化 ActionProposal；观测响应式 MockProvider 固定标记 `is_real_model=false`。Policy adapter 将执行委托到 ToolGateway。
- 独立 PolicyValidator 对权限、动作白名单、参数、预算、禁止动作和重复动作做 fail-closed 检查；执行后检查和停止策略保持独立语义。
- 单进程授权凭证支持 Run/参数绑定、nonce 原子一次性消费、预算预留/释放、过期拒绝、同 Run 串行；SecretResolver 仅解析授权的 `TG_SECRET_*` 引用并拒绝越权、缺失和路径穿越，不回显明文。
- DecisionRecord 写入 Trace Hash v3；v1/v2 规范化载荷不变，v3 摘要覆盖 proposed action、policy decision、decision ID/source 及 scenario ID/version/digest，逐字段篡改验证失败。
- Browser observation 敏感字段识别覆盖 password、autocomplete、Scenario sensitive_selectors；危险/破坏性动作继续被 Gateway 与 validator 拒绝。

## 验收结果

- M3 组件与真实 Chromium 闭环测试在聚焦回归集合中通过；Planner → PolicyValidator → ToolGateway → Browser → evaluator → Trace Hash v3 路径由真实浏览器用例覆盖。
- 授权并发/nonce、预算、过期、重放、SecretResolver 错误路径、历史 Trace 兼容和篡改检测均有独立测试。
- 最新提交通过 GitHub CI 5/5；Python job 766 passed / 7 skipped；安全、Web、Product E2E、Browser E2E 全部成功。完整本机门禁数据及 skip 原因见 [M1 报告](R5-5.3-M1-实施与验收报告.md)。

## 结论与边界

M3 的 Scripted/Mock 决策闭环门禁通过。M4 真实 LLM 仍为 `NOT_RUN / 409 BLOCKED`，等待 D8 正式批准；本报告不把 Mock 结果描述为模型能力或真实 LLM 验收。
