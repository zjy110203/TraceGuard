## 2. 探索状态语义修正

**改动文件**：`packages/agents/exploration.py`、`packages/agents/explorer.py`

- 三个正交状态轴：
  - 执行状态 `ExplorationStatus`：COMPLETED / FAILED / CANCELLED；
  - 停止原因 `StopReason`：`GOAL_VERIFIED` / `PLAN_EXHAUSTED` / `STEP_BUDGET` / `TOOL_CALL_BUDGET` / `TIME_BUDGET` / `POLICY_STOP` / `ERROR`。**`GOAL_REACHED` 已移除**，策略脚本耗尽 = `PLAN_EXHAUSTED`；
  - 目标验证 `GoalStatus`：VERIFIED / NOT_VERIFIED / INCONCLUSIVE / NOT_EVALUATED。
- 新增 `evaluate_goal(intent, observations)`：仅以观察证据判定（target 路径比对、expected_outcomes 文本比对、`state.*` 断言标记 deferred 交由正式运行 Oracle）；无目标声明 = NOT_EVALUATED；无可用观察 = INCONCLUSIVE。
- 仅当执行正常结束且目标评估 VERIFIED 时，stop_reason 才升级为 `GOAL_VERIFIED`；预算耗尽永远不是目标证据。
- 策略决策本身抛错（schema 失败、drift、白名单拒绝）记录为 decision `ERROR` 并以 POLICY_STOP 终止，不再伪装成完成。
- 前端 ExplorerView 以三行独立展示执行状态 / 停止原因 / 目标验证，并渲染逐条 goal checks（含 deferred 标记）。

## 3. Compiler 严格依据目标生成断言

**改动文件**：`packages/agents/compiler.py`（COMPILER_VERSION 1.1.0 → 1.2.0）

- `_expected_path()` **删除观察路径回退**：目标路径只来自 `intent.target`；无 target 时生成 url 断言并在 checklist 中要求人工确认依据。
- 编译硬准入 `_require_verified_goal()`：`evaluate_goal` 非 VERIFIED 一律 `ValidationError(GOAL_NOT_VERIFIED)`，覆盖规范全部五个场景：
  - A 正确登录 → VERIFIED → 编译通过（真实浏览器验证）；
  - B 错误密码（停留在 /login）→ NOT_VERIFIED → 拒绝；
  - C 预算耗尽 → NOT_VERIFIED / INCONCLUSIVE → 拒绝；
  - D 未填写目标 → NOT_EVALUATED → 拒绝；
  - E 目标与实际页面不一致 → NOT_VERIFIED（checks 中给出 expected/observed）→ 拒绝。
- 文本断言仅来自 `intent.expected_outcomes` 且必须在最终观察中出现；独立业务断言仅来自 `intent.required_assertions`；禁止猜测数据库期望值；click 成功仍不能成为 Oracle（validate 保留）。

## 4. Trace 完整性升级

**改动文件**：`packages/agents/exploration.py`、`apps/api/candidate_api.py`

- Trace Hash **v2**（`hash_version=2`）规范范围：exploration_id、test_intent、action_sequence、observations、agent_decisions、security_events、stop_reason、agent/prompt/tool/application/browser 版本。**排除**派生字段（status、step_count、goal 评估、trace_integrity_verified、redacted_fields 等），避免自引用。
- 哈希在脱敏后计算（沿用既有红线管道）；写入后按 JSON round-trip 重算验证（既有逻辑保留）；`GET /explorations/{id}` 读取时重验。
- **v1 兼容**：无 `hash_version` 的历史记录按 v1 公式重验，历史轨迹不会被误判为篡改（`test_legacy_records_still_verify_with_v1_scope`）。
- 编译准入链（`_exploration_record`）：读取 Exploration → `verify_trace_record` → 恢复 TestIntent → 重算目标状态并与记录值比对 → Compiler → Candidate；任一失败 404/409/422 拒绝。
- 篡改测试（`tests/test_trace_integrity_v2.py`）：改 intent / 改 agent_decisions / 改版本字段 / 改动作 / 改观察 / 旧 hash 重放全部被检出；派生字段修改不影响验证。

## 5. Candidate 审核机制完善

**改动文件**：`apps/api/candidate_api.py`、`apps/web/src/views/CandidatesView.vue`、`packages/agents/compiler.py`

- 审核清单结构化：`review_checklist` 变为 `{id, text, required}` 列表（如 `chk-target-path`、`chk-destination-marker`、`chk-oracle-basis`），兼容旧字符串格式读取。
- 详情页完整展示规范要求的全部 14 项：原始 TestIntent（goal/expected_outcomes/target/required_assertions/constraints）、全部正式步骤（含 value_ref 列）、TestDataRef 对应表、探索观察结果（末 4 条）、断言与 Oracle（source_ref / expected_value / source / approved）、不确定项、审核清单。
- **服务端强制审核确认**（`ReviewRequest.review_confirmed` + `uncertainty_acknowledged`）：
  - 未确认全部必需项 → 422 并返回缺失 id 列表；确认了未知 id → 422；存在不确定项且未显式确认 → 422。

  - 审批记录保留 reviewer / approval_record / reviewed_at / review_confirmed 明细；`reviewer_is_local_audit_field: true` 明确标注 reviewer 仅为本地审计字段。
- 拒绝理由改为必填（422），拒绝记录保留 reason。

## 6. scripted-agent 决策环（§3.6）

**新文件**：`packages/agents/scripted_agent.py`、`tests/test_scripted_agent.py`

- `ScriptedAgentPolicy`：Observation → LLMPolicy（DECISION_SCHEMA 校验 + 工具白名单）→ ScriptedProvider（预编排 JSON 决策，`NOT_REAL_INFERENCE`）→ ToolGateway → PlaywrightAdapter → Result → 下一 Observation。
- 每个决策携带观察期望（url_path / title / testid），**必须与当前 Observation 匹配**才应用，页面漂移触发 `ScenarioDriftError` 并大声停止——证明策略真的消费新鲜观察。
- 不调用真实模型、不读取任何 Key、`agent_version` 携带 `NOT-REAL-INFERENCE` 标记、provider call traces 记录 prompt/response hash 与 schema 校验结果。
- Explorer 级真实浏览器集成测试覆盖：正常完成（5 决策全审计）、逐步观察消费、非法工具拒绝、决策漂移、步数预算耗尽、错误动作恢复。`scripted`（固定脚本，不消费观察）与 `scripted-agent` 在 POLICIES 目录中明确区分。
