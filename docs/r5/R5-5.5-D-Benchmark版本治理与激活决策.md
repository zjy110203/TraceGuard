# R5-5.5 D：Benchmark 版本治理与激活决策

状态：**设计准备 / 未激活 / 等待具名审批**。没有修改 GT 标签、历史实验或正式 Oracle；真实归因准确率仍为 `null`，状态 `BLOCKED`。

## 当前源码事实

- `GroundTruthManager` 的 `_version` 固定为 `gt-v1`，记录按 `scenario_id` 单键存储。
- `BenchmarkStore.load_gt_versions()` 逐个校验 payload SHA-256，但 `restore()` 按文件名排序读全部 GT，同一 `scenario_id` 首次插入后，后续版本被忽略。
- `DatasetManager.create()` 依据当前 manager 的版本和有序 scenario ID 生成版本串；restore 从 Dataset 文件读取 ID/分区/场景后，再调用当前 `create()`，会依赖当前 GT Manager 重建 Dataset。
- `ExperimentResult` 持有 `dataset_id`，其 metadata 可记入运行参数；历史记录不强制绑定可复算的 GT envelope 摘要。
- `benchmark.gt_import` 能严格追加一份离线、具名批准的 GT envelope；它不负责激活，不改正式 Oracle。

这些实现事实说明“目录里有 gt-v2.json”并不等于特定 Dataset 或 Experiment 使用 gt-v2。

## 推荐的显式身份模型

每个 GT envelope 固定绑定：

- `gt_version`：不可变版本 ID；
- `payload_sha256`：当前既有 payload 摘要算法的摘要；
- `file_sha256`：实际 envelope 原始字节摘要，用于备份/传输后原字节比对；
- `approval_record`、具名 reviewer、带时区批准时间和 authority refs；
- 完整、无重复 scenario 清单及标签词表版本。

加载键应为 `(gt_version, scenario_id)`。同版本重复 scenario、版本缺失、未批准版本、摘要不符或标签不完整均 fail closed。禁止“目录最新”“排序第一”或旧值 fallback。

Dataset manifest 应不可变绑定：`dataset_id`、`dataset_version`、分区、`gt_version`、`gt_payload_sha256`、有序 scenario ID 列表、创建时间和 manifest 摘要。恢复时验证并按 manifest 原样重建，不调用活动 GT manager 重算版本。

每个 Experiment 要记录并在结果中回显 `dataset_id/version`、`gt_version`、`gt_payload_sha256`、评测引擎版本、方法、参数摘要和审批/激活决策 ID。历史 Experiment 缺这些信息时标记 `LEGACY_UNBOUND`，保留原记录但不推断使用哪个 GT，也不改写其指标。

## GT 导入、批准与激活分离

建议流程：

```text
离线生成候选映射
 → 具名负责人逐项批准新 GT 版本
 → 原子追加不可变 envelope
 → 第二次显式批准激活决策（绑定 GT version + SHA）
 → 创建绑定该 GT 的新 Dataset
 → 显式启动新 Experiment
 → 结果持久化 GT/Dataset/Engine 身份
```

GT 数据批准和评测激活是两个独立决定。激活请求必须提交精确的 version、摘要、Dataset manifest 和 authority record；当前活动版本、默认参数、文件顺序均不应提供隐式选择。切换后新实验使用新版本，历史实验仍绑定原 manifest。

## 不允许的恢复行为

- 不按文件名或 mtime 选“最新 GT”。
- 不把多个版本相同 scenario 的标签合并。
- 不因历史 Dataset 缺少新字段而用当前 GT 重新计算其身份。
- 不因审批记录缺失、摘要损坏或版本文件缺失而退回 gt-v1 并继续评测。
- 不原位编辑旧 GT 文件或 Experiment 结果。
- 不将 synthetic 夹具的审批字段或映射当成真实项目负责人批准。

遇到 legacy 未绑定数据时，允许读取原始字节和展示历史结果，但明确标记版本身份缺失；任何新指标计算都须显式阻断。

## 测试矩阵（后续实现准入）

| 情况 | 预期 |
|---|---|
| 同目录 gt-v1/gt-v2，运行顺序互换 | 版本选择精确、不受排序影响 |
| 同一 scenario 在 v1/v2 标签不同 | Dataset/Experiment 只读取指定版本 |
| 重启后恢复已保存 Dataset/Experiment | 原始版本和摘要保持不变 |
| 版本文件缺失/摘要损坏/approval 缺失 | 启动或该实验 fail closed，不 fallback |
| Dataset manifest 场景顺序/摘要变化 | 校验失败，不重算覆盖 |
| Experiment 引用未批准 GT | 拒绝创建/执行 |
| legacy Experiment 无 GT 版本绑定 | 标记 `LEGACY_UNBOUND`，不改写 |
| 真实标签未经具名审批 | 不可导入/激活，指标持续 BLOCKED |
| 实验结果和原 GT 文件复核 | 摘要、版本、标签原字节可重算 |
