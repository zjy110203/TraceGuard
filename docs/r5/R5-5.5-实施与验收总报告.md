## 范围和结果

R5-5.5 补齐 Explorer 业务证据、SUT 数据隔离、离线 shared/separate 多数据库备份恢复验证，并交付 Repair Generator 和 Benchmark 版本治理决策包。

| 工作流 | 交付 / 约束 |
|---|---|
| A：独立业务证据 | TeamFlow Eval run-scoped seed/cleanup、公开业务状态快照、State Hash / delta、Evidence availability 与 cleanup 审计；不覆盖 Test Verdict / Oracle / Trace |
| B：多数据库恢复 | 离线备份 v2、明确 shared/separate、v1 shared 读取、全历史引用与真实浏览器恢复校验；副本保持未激活 |
| C：Repair Generator | 只交付准入与接口决策包；本轮没有生成器实现，真实 E2E 通过人工编辑 Locator 并走现有人工审批 / Sandbox / CAS |
| D：Benchmark 版本治理 | 只交付版本身份与批准 / 激活分离方案；不修改 GT / 历史 Experiment，不激活新版本；准确率维持 `null / BLOCKED` |

2.1.0 scenario 版本保持显式 opt-in；历史 digest 与记录不改写。负向或不可验证路径编译仍须 409。C05 / C06 / C11 / C12 不在本轮修改范围。D8 真实 LLM 仍 BLOCKED，没有模型请求。

## 集成闭环

真实 Chromium 验收经过 Explorer、Candidate 人工审核、FAILED Run、SUPPORTED Diagnosis、手工 Locator 修改、Repair 人工审批、Sandbox replay、Promotion、进程重启、Regression、Rollback、再次重启、旧版本预期失败。之后以 separate v2 topology 离线备份与恢复，并从恢复历史读取 Chains、Cases、Repairs、Evidence 和 Blobs，再执行恢复副本的真实业务浏览器路径。综合 pytest：1 passed，93.25 秒。

离线恢复副本报告：22 个 payload 文件，1 个 Exploration、1 个 Candidate / Candidate transaction、4 条 Chains、4 个验证 Blob、11 个 Repair snapshots、5 个正式 Case 版本；历史 API、schema 归属、TeamFlow 与 Platform 启动以及浏览器业务状态均 PASS。摘要见 [A 报告](R5-5.5-A-独立业务证据与SUT隔离验收报告.md)、[B 报告](R5-5.5-B-多数据库离线备份与恢复验收报告.md) 及 [归档结果](evidence/r5-5.5/)。

## 源码复审及剩余限制

源码复审发现并修正分库部署下 Repair Sandbox 子进程可能继承 Platform DB URL 的问题；另外收紧 TeamFlow table creation、恢复 schema / 历史引用检查，并关闭备份校验中 SQLite 只读句柄。代码评审详见 [源码复审与可靠性报告](R5-5.5-源码复审与可靠性报告.md)。

当前仍为单机、单进程和 SQLite 范围。离线备份要求操作员先停止所有写入者。Repair Generator 只是设计，不可调用；GT / 正式指标未批准；真实 LLM、身份认证、分布式写入和在线备份仍需独立阶段与具名审批。清单见 [剩余功能与后续阶段](R5-5.5-剩余功能与后续阶段清单.md)。
