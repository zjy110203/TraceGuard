# R5-4.7 实施报告：浏览器安全与执行可靠性

- 基线 Commit：`c6e2efb09975bd418959a4f8083cd6b4b4595257`（main，叠加未提交 R5-4 收口改动）
- 验证环境：Windows 11 / Python 3.13.14 / Chrome 157.0.8103.79 / Playwright 1.65.2

## 1. 统一浏览器网络安全边界（§4.1）

**新文件**：`packages/execution/netpolicy.py`（`OriginPolicy` + `normalize_origin`）
**改动**：`packages/execution/browser.py`、`packages/agents/explorer.py`、`packages/execution/runner.py`

- 单一实现、两个消费方：Explorer 的 `PlaywrightAdapter` 与正式执行的 `BrowserManager` 现在使用**同一个** `OriginPolicy`（原先两处各自实现，且正式执行侧完全没有网络层防护）。
- 权限模型：精确 `scheme://host:port` origin（默认端口显式化）+ 主机名白名单；`data:`/`blob:`/`about:` 视为页内无出网；userinfo URL 直接拒绝；`localhost` 与 `127.0.0.1` 是不同 origin。
- `BrowserManager` 新增请求安全网关：
  - `context.route("**/*", guard)` 覆盖导航、子资源（img/js/css/fetch/XHR）、iframe、WebSocket；
  - popup 一律关闭并记录；download 一律取消并记录；
  - navigate 前检查请求 URL，goto 后检查**最终 URL**，重定向落地未批准 origin 时弃页（about:blank）并判步骤失败；
  - 所有被拒请求记录到 `blocked_requests`（上限 50，防刷屏），并生成 `network_blocked` Evidence + `security.request_blocked` 事件（`BrowserManager.security_evidence`，已接入 LocalRunner）。
- `LocalRunner` 默认权限 = 目标 base_url 的精确 origin（`OriginPolicy.for_base_url`），调用方可收窄不可放宽。
- Explorer 侧修复：原先 `_approved()` 只查 scheme+host，**不查端口**——同 IP 不同端口的子资源会被放行；现与 gateway 同源策略。
- 一致性测试 `test_toolgateway_and_originpolicy_agree`：对 URL 矩阵，ToolGateway 的 navigate 判定与路由网关判定完全一致。

**测试矩阵结果**（`tests/test_network_gateway.py`，双本地端口 + 真实 Chrome）：

| # | 场景 | 结果 |
| --- | --- | --- |
| 1 | 正常本地目标 | 放行 |
| 2 | 同 IP 不同端口 | 拒绝 |
| 3 | 同 IP 不同 scheme（https） | 拒绝 |
| 4 | localhost vs 127.0.0.1 | 区分（拒绝） |
| 5 | 跨 origin 重定向 | 步骤失败、弃页、不落地攻击源 |
| 6 | 外部图片 | route abort，攻击服务器 0 命中 |
| 7 | 外部 JS | route abort |
| 8 | iframe | route abort |
| 9 | Popup | 关闭并记录 |
| 10 | WebSocket | 关闭（route + ws handler 双保险） |
| 11 | 下载 | 取消/abort 并记录 |
| 12 | 页面发起 fetch | route abort |

## 2. TestDataRef 安全性（§4.2）

**改动**：`packages/execution/models.py`、`tests/test_dataref_security.py`

- 新增结构约束：**敏感 TestDataRef（ref_id 命中 SENSITIVE_HINT）携带内联 value → `TestCaseVersion.validate()` 报错**——凭据只能由部署级 TestDataProvider 运行时解析。
- 既有约束全部保留并逐条测试锁定：value_ref+明文并存、未声明 value_ref、占位符作为输入、占位符+无 ref 组合。
- 运行时保证：
  - 未解析 ref / 占位符输入 → BLOCKED 报告，**不启动浏览器**、不产生任何步骤执行；
  - 运行时解析出的明文只存在于内存绑定步骤中，RunReport JSON 与落盘报告文件均不包含明文（测试断言）；
  - 日志/Trace/Candidate/Case 不泄漏明文：Explorer 红线管道 + compiler `extract` 的 value_ref 绑定（value 恒为空）覆盖。
- `resolve_step_value` 六种非法/合法组合均有测试。

## 3. 持久化错误处理修复（§4.3）

**改动**：`apps/api/chain_api.py`、`packages/execution/orchestrator.py`、`packages/evidence/manager.py`、`packages/core/persistence.py`（未改分类规则，仅被测试锁定）

### A. Producer 注册异常
`_persist_events()` 中 `store.register_producer()` 移入分类 try 块：EventStore 不可用现在按事件分类为 DEPENDENCY_UNAVAILABLE/FAILED 并进入 `failures`，不再是裸 500，也不会与 DUPLICATE 混淆。

### B. Screenshot 字节不再静默丢失
- `EvidenceManager.import_record` 将 blob 元数据（key/size/sha256）**回写**到调用方 record，但**不删除** hex 字节；
- `_strip_screenshot_bytes` 改为条件剥离：仅当 ① 记录 WRITTEN/DUPLICATE、② blob key 存在且可读、③ 重哈希校验通过、④ 记录摘要与 blob 一致，四个条件同时满足才从 Chain Report 删除字节；
- 任何一条不满足 → 字节保留为恢复数据，并在 evidence 计数中追加 `RETAINED_FOR_RECOVERY` 条目，status 升为 PARTIAL。

### C. 整体状态聚合
`FAILED` 现在支配 `PARTIAL`（原先 PARTIAL 优先，总失败会被美化）。三态定义按规范：FAILED=至少一个必需阶段完全失败；PARTIAL=部分成功；OK=全部成功或幂等存在。

### D. Run 与 Chain 状态一致性
- 五个状态轴在 chain 摘要中分离暴露：`execution_status` / `test_verdict`（执行内）、`persistence_status`、`graph_status`、`chain_status`；
- `chain_status`：任一 stage FAILED → FAILED；任一 PARTIAL → PARTIAL；否则 completed=OK / 未完成=FAILED——持久化失败不再显示为完整成功；
- orchestrator：`after_run` 抛异常时合成 `persistence FAILED` 阶段，同时写入 Run 进度与 report.stages（原先只塞一个 `{"error"}` dict，阶段不可见）。

### E. 异常注入测试（`tests/test_chain_persistence_failures.py`，12 项）

| 场景 | 结果 |
| --- | --- |
| 1 EventStore 不可用 | DEPENDENCY_UNAVAILABLE，status=FAILED |
| 2 Producer 注册失败 | 分类记录，registered 为空 |
| 3 EvidenceManager 写入失败 | FAILED + failures 明细 |
| 4 BlobStore 写失败 | hex 字节保留在报告（恢复数据） |
| 5 Blob 读取/校验失败 | 字节不释放 |
| 6 DB 连接中断 | "connection refused"→DEPENDENCY_UNAVAILABLE |

| 8 全部重复写入 | 幂等无冲突 |
| 9 重复 ID 不同内容 | `import_record` 拒绝（integrity_check 比对），分类为 FAILED 而非 DUPLICATE |
| 10 Run 完成但 ChainStore 保存失败 | 合成 persistence FAILED 阶段；Run=COMPLETED（执行轴）/ chain_status=FAILED（完成轴），两轴分离可查询 |

## 4. FullChain 生命周期边界（§4.4）

**改动**：`packages/execution/orchestrator.py`、`tests/test_chain_lifecycle.py`

- `chain.run` 抛异常 → Run 立即 finalize 为 FAILED（含原因）后重抛，**不再遗留 RUNNING**；
- after_run 持久化异常 → 阶段状态完整（见 §3.D）；
- ChainStore 保存失败 → Run 行的 report JSON 携带失败原因，可经 `/runs/{id}/report` 查询；
- 取消释放浏览器：cancel 经 between-step abort hook 触发，BrowserManager 上下文退出关闭浏览器（既有机制，test_cancel_mid_flight 覆盖）；单个 Playwright 动作阻塞时取消的实际边界 = 该动作自身的 timeout（`max_action_s`），已在报告注明（设计边界，不新增基础设施）；
- 同一 Run ID 贯穿全链（run_id_override，既有，测试锁定）；
- 未新增 Redis/Celery 等基础设施，保持单机 Dispatcher 架构。

## 5. 浏览器通道统一

新增 `browser_channel()`（`packages/execution/browser.py`）：默认系统 Chrome；`TRACEGUARD_BROWSER_CHANNEL=""` 时用 Playwright 内置 Chromium。Explorer、BrowserManager、workbench UI 测试、journey E2E 统一走该函数，消除 CI 与本机通道漂移（CI 无系统 Chrome → Python job 现在可真正跑浏览器测试）。

## 7. 遗留与后续

- `S3BlobStore.verify` 未实现（unverified adapter，显式抛错）；对象存储接入属后续阶段。
- 单动作阻塞期间取消无法即时生效（Playwright sync API 限制），由动作超时兜底；异步化需引入驱动级并发，保留给 R5-5 评估（优先复用现有 Dispatcher）。
- Evidence import 的 DUPLICATE 判定基于 integrity_check；同一 evidence_id 重放相同内容幂等、不同内容拒绝，不比较 payload 全文（避免把脱敏前后视为冲突）。
