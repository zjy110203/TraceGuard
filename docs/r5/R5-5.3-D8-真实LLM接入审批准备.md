## 1. 调用范围（Scope）

### 1.1 允许的调用

| # | 允许 | 说明 |
|---|---|---|
| 1 | Agent Planner 的决策推理 | Observation + 上下文 → Action Proposal（结构化） |
| 2 | 连通性探测 | `scripts/verify_llm_provider.py` 一次性探测（现有，非产品路径） |
| 3 | 隔离试运行 | 限定场景（teamflow-login/project-create）、限定预算、限定并发 1 |

### 1.2 明确排除（真实 LLM 不得负责）

1. **决定最终业务 verdict** —— GOAL_VERIFIED 只能来自 Goal Evaluator 的断言求值；
2. **绕过安全策略** —— OriginPolicy / denied_actions / 预算闸由 Policy Validator 强制，模型无权覆盖；
3. **自主审批 Candidate** —— `review_confirmed` + `uncertainty_acknowledged` 人工门禁不动；
4. **修改 GT** —— GT 对 Agent 永久隔离（Benchmark 红线）；
5. **自动批准 Repair** —— Repair 闭环人工批准不动；
6. **直接执行未经授权的危险动作** —— 执行唯一通道 ToolGateway，模型只能提案。

### 1.3 调用方拓扑

```
Explorer 决策环
  → Context Builder（脱敏后上下文）
  → Agent Planner ──(HTTP)──> DeepSeek chat/completions（OpenAI 兼容）
  → Action Proposal（JSON Schema 强校验）
  → Policy Validator → ToolGateway → 浏览器
```

模型出口只有 1 个（Planner），执行入口只有 1 个（ToolGateway）。

## 2. Provider 设计（DeepSeek / OpenAI 兼容）

### 2.1 三模式不可混淆（强制区分）

| 模式 | 实现 | `is_real_model` | `may_contain_real_inference` | 用途 | UI/报告标注 |
|---|---|---|---|---|---|
| **ScriptedProvider** | `llm.py`（已有） | False | False | 确定性脚本回放（测试/开发） | `NOT-REAL-INFERENCE` |
| **MockProvider** | 🆕 新增 | False | False | 闭环验证的确定性假模型（按观测返回预设结构化输出） | `NOT-REAL-INFERENCE` |
| **RealProvider** | `OpenAICompatibleProvider`（已有） | True | True | 真实推理（本审批对象） | 真实模型名 + `may_contain_real_inference=True` |

- 三者共用 `LLMProvider` Protocol 与 `TracedClient`；
- Scripted/Mock 的输出**永不**标注为真实推理；报告统计必须按模式分列；
- 混淆三模式视为验收失败（风险 R10）。

### 2.2 Provider 选型基线

- 协议：OpenAI 兼容 `POST /chat/completions`（`llm.OpenAICompatibleProvider` 已实现骨架）；
- 首选：DeepSeek（`https://api.deepseek.com/v1`，`DEEPSEEK_API_KEY`）；
- 备选：任何 OpenAI 兼容端点（`OPENAI_API_KEY`），切换只改环境变量，不改代码路径；
- 温度：默认 `0.0`（降低随机性；调高需在审批中单独说明）；
- 结构化输出：`response_format: json_object` + 本地 JSON Schema 校验（双保险）。

## 3. API Key 安全管理

| 要求 | 方案 | 现状 |
|---|---|---|
| 存储 | 仅环境变量（`DEEPSEEK_API_KEY` / `OPENAI_API_KEY`），`.env` 不入库 | ✅ `provider_from_env` 只按**名**检查 |
| 读取 | 值不读取、不日志、不入 Trace、不进错误消息 | ✅ 现有设计 |
| 回显 | 任何 API/UI/报告禁止回显密钥；只显示"已配置/未配置" | ✅ |
| 轮换 | 密钥轮换 = 环境变量替换 + 重启服务，无持久化副本 | ✅ |
| 测试隔离 | 测试套件**禁止**携带真实密钥；无密钥行为 hermetic 测试 | ✅ `test_llm_policy.py` 纪律 |
| 最小权限 | 建议使用独立子账号/限额 key（平台侧操作，列入审批条件） | 📋 待办 |

## 4. 模型版本与 Prompt 版本记录

| 项 | 记录位置 | 说明 |
|---|---|---|
| `model_version` | 每条决策记录 + Trace | 实际返回的模型名（如 `deepseek-chat`） |
| `prompt_version` | 每条决策记录 + Trace + 哈希 | 模板版本号（如 `planner-v1`），模板变更必须升版本 |
| Prompt 内容 | **不存明文** | 只存 sha256 + 字符数（`CallTrace` 既有设计） |
| 上下文版本 | `context_version` | Context Builder 格式版本，进 prompt hash |

复核要求：任取一条真实决策，应能回答"哪个模型、哪版提示词、哪版上下文"，且无法从 Trace 还原敏感原文。

## 5. Structured Output

- 输出必须通过 `TracedClient.complete_structured` + `Draft202012Validator` 校验；
- Action Proposal schema 严格（未知字段拒绝，枚举校验，confidence ∈ [0,1]）；
- 校验失败 → 重试（≤ `max_retries`）→ 仍失败则 `StructuredOutputError`：
  **不产生决策、不伪造动作**，按 §7 降级或停止；
- 每次调用（含失败）都进 `CallTrace`（schema_ok 标记）。

## 6. Token 统计与费用核算

### 6.1 统计

| 指标 | 来源 | 记录 |
|---|---|---|
| `prompt_tokens` / `completion_tokens` | 响应 `usage` 字段 | 每次调用入 CallTrace |
| 累计 token | 按探索/按日聚合 | 费用台账 |
| 延迟 / 重试次数 | 客户端测量 | CallTrace（现状） |

### 6.2 费用核算与上限

| 闸 | 默认值 | 行为 |
|---|---|---|
| 单次调用输出上限 | `max_output_tokens=512`（现状） | 超出截断/报错 |
| **单次探索费用上限** | **≤ $0.50** | 超限 → 硬停（`BUDGET_EXHAUSTED`），不再发起任何调用 |
| **单日费用上限** | **≤ $20.00** | 超限 → 当日全部真实调用拒绝（409 语义保持） |
| 记账 | 每次调用按价目表估算费用并累计 | 入 Trace（`cost` 字段）与费用台账 |
| 价目表 | 配置项 `cost_per_1k_tokens`（输入/输出分列） | 模型换代时更新并升配置版本 |

- 上限值**只允许下调，不允许上调**（上调需重新走 D8）；
- 估算口径保守（宁可提前停，不可超支）；
- 费用台账独立于 Trace，按日归档。

## 7. 超时、重试与失败降级

| 项 | 参数（默认） | 说明 |
|---|---|---|
| 单次调用超时 | `timeout_s=30` | 现状 |
| 重试 | `max_retries=2` | 现状；指数退避（M4 实施） |
| HTTP 5xx / 超时 | 重试后仍失败 → `LLMError` | 不伪造决策 |
| 结构化输出失败 | 重试后仍失败 → `StructuredOutputError` | 不伪造决策 |

**降级策略（二选一，由场景声明）：**

1. `degrade: scripted` —— 回退 ScriptedProvider 兜底，trace 标注 `degraded_from=real`，
   **报告不得当作真实推理结果统计**；
2. `degrade: stop` —— 直接停止（`ERROR` / `EXECUTION_FAILED`），不猜测动作。

红线：模型失败**绝不**产生"看起来合理"的伪造决策。

## 8. 决策记录（审计）

每次真实调用记录（`CallTrace` + DecisionRecord，见台账 §9-E）：

- decision_id / proposed_action 全文（脱敏后）/ policy_decision / execution_result；
- prompt_sha256 / response_sha256 / token / latency / attempts / schema_ok；
- model_version / prompt_version / context_version；
- cost（本次估算）与累计费用。

复核语义：真实决策**可复核**（人工审计上下文与理由），**不假装可重放**（模型随机输出不可字面复现）。

---

## 9. 敏感数据脱敏

| 数据 | 处理 |
|---|---|
| 密码/凭据 | 只从受信配置注入动作参数；trace/日志/prompt 全链路脱敏（`redact_actions` 既有） |
| 表单输入值 | **从不采集**（红线：密码不是 observation） |
| 页面文本 | prompt 可含脱敏后的观测文本；trace 只存 sha256 |
| GT / 审计数据 | 不进 prompt、不进 trace |
| 内部路径/密钥 | 错误消息过滤（既有纪律） |

## 10. 人工启用开关（Kill Switch）

| 项 | 设计 |
|---|---|
| 默认状态 | **关闭**（`llm` 策略 409 BLOCKED 保持） |
| 开启条件 | D8 批准 + 操作者显式设置环境开关（如 `TG_REAL_LLM=1`）+ 密钥存在 |
| 运行时开关 | 一键关闭 → 下一决策环立即回到 Scripted 行为；进行中调用允许完成但不追加 |
| 关闭后残留 | 无状态残留（无缓存决策复用）；已产生的真实决策 trace 保留（审计） |
| 应急 | 出现费用异常/危险动作趋势 → 先关开关，再分析 trace |

## 11. 风险与回滚方案

### 11.1 风险清单（D8 视角）

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| D1 | 费用失控 | 中 | 单次/单日硬闸 + 独立限额 key + 费用台账 |
| D2 | 模型幻觉导致危险动作 | 中 | 单通道执行 + 六项执行前检查 + denied_actions |
| D3 | 幻觉 claim（假成功） | 中 | 模型永不裁决 verdict；断言独立求值 |
| D4 | 敏感数据外发 | 低 | 全链路脱敏 + 不采集输入值 + prompt 只发观测 |
| D5 | 三模式混淆 | 低 | is_real_model 硬标记 + UI 强展示 + 验收断言 |
| D6 | 供应商不可用 | 低 | 超时/重试/降级；不影响 Scripted 路径 |
| D7 | 审计断链 | 低 | decision_id 链 + Trace Hash v3 + CallTrace 全量 |

### 11.2 回滚方案

| 触发 | 回滚动作 | 生效时间 | 影响面 |
|---|---|---|---|
| 费用异常 | 关闭开关 | 下一决策环 | 仅真实推理停用 |
| 危险动作趋势 | 关闭开关 + 复盘 trace | 立即 | 同上 |
| 模型输出质量问题 | 降级 scripted / 关闭 | 立即 | 同上 |
| 密钥泄露 | 轮换密钥 + 关闭开关 | 立即 | 无持久化副本需清理 |
| 全量回退 | `TG_REAL_LLM=0` | 立即 | 产品回到 R5-5.2 行为，无迁移成本 |

回滚验证：关闭后跑 `test_llm_policy.py` + 场景回归（Scripted 路径），确认 409/`NOT-REAL-INFERENCE`
行为恢复——这是回滚的验收标准。
