## 1. 调用范围（Scope）

### 1.1 允许的调用

| # | 允许 | 说明 |
|---|---|---|
| 1 | Agent Planner 的决策推理 | Observation + 上下文 → Action Proposal（结构化） |
| 2 | 连通性探测 | `scripts/verify_llm_provider.py` 一次性探测（现有，非产品路径） |
| 3 | 隔离试运行 | 限定场景（teamflow-login/project-create）、限定预算、限定并发 1 |

### 1.2 明确排除（真实 LLM 不得负责）

1. **决定最终业务 verdict** —— GOAL_VERIFIED 只能来自 Goal Evaluator 的断言求值；
2. **绕过安全策略** —— OriginPolicy / denied_actions / 预算闸由 Policy Validator 强制，模型无权覆盖；
3. **自主审批 Candidate** —— `review_confirmed` + `uncertainty_acknowledged` 人工门禁不动；
4. **修改 GT** —— GT 对 Agent 永久隔离（Benchmark 红线）；
5. **自动批准 Repair** —— Repair 闭环人工批准不动；
6. **直接执行未经授权的危险动作** —— 执行唯一通道 ToolGateway，模型只能提案。

### 1.3 调用方拓扑

```
Explorer 决策环
  → Context Builder（脱敏后上下文）
  → Agent Planner ──(HTTP)──> DeepSeek chat/completions（OpenAI 兼容）
  → Action Proposal（JSON Schema 强校验）
  → Policy Validator → ToolGateway → 浏览器
```

模型出口只有 1 个（Planner），执行入口只有 1 个（ToolGateway）。

## 2. Provider 设计（DeepSeek / OpenAI 兼容）

### 2.1 三模式不可混淆（强制区分）

| 模式 | 实现 | `is_real_model` | `may_contain_real_inference` | 用途 | UI/报告标注 |
|---|---|---|---|---|---|
| **ScriptedProvider** | `llm.py`（已有） | False | False | 确定性脚本回放（测试/开发） | `NOT-REAL-INFERENCE` |
| **MockProvider** | 🆕 新增 | False | False | 闭环验证的确定性假模型（按观测返回预设结构化输出） | `NOT-REAL-INFERENCE` |
| **RealProvider** | `OpenAICompatibleProvider`（已有） | True | True | 真实推理（本审批对象） | 真实模型名 + `may_contain_real_inference=True` |

- 三者共用 `LLMProvider` Protocol 与 `TracedClient`；
- Scripted/Mock 的输出**永不**标注为真实推理；报告统计必须按模式分列；
- 混淆三模式视为验收失败（风险 R10）。

### 2.2 Provider 选型基线

- 协议：OpenAI 兼容 `POST /chat/completions`（`llm.OpenAICompatibleProvider` 已实现骨架）；
- 首选：DeepSeek（`https://api.deepseek.com/v1`，`DEEPSEEK_API_KEY`）；
- 备选：任何 OpenAI 兼容端点（`OPENAI_API_KEY`），切换只改环境变量，不改代码路径；
- 温度：默认 `0.0`（降低随机性；调高需在审批中单独说明）；
- 结构化输出：`response_format: json_object` + 本地 JSON Schema 校验（双保险）。

### 2.3 Provider 出站限制（D8 整改）

**真实模型只能访问获批的 Provider endpoint。不能因为采用 OpenAI 兼容接口就允许任意 URL。**

| 约束 | 值 | 实现方式 |
|---|---|---|
| 允许的 endpoint 白名单 | `https://api.deepseek.com/v1`、`https://api.openai.com/v1` | `PROVIDER_ENV` 配置（现状硬编码） |
| 禁止任意 URL | 即使 base_url 可配置，也只允许白名单内的 endpoint | 构造时校验 base_url ∈ 白名单 |
| 禁止 HTTP（明文） | 仅允许 HTTPS | URL scheme 校验 |
| 禁止内网地址 | 不允许 `127.0.0.1` / `10.*` / `172.16-31.*` / `192.168.*` 等 | 目标 IP 检查（防 SSRF） |
| DNS rebinding 防护 | 复用 `UrlGuard` 既有能力 | 连接时校验解析 IP |
| 请求超时 | `timeout_s=30`（现状） | httpx timeout |
| 响应大小限制 | ≤ 64 KB | 防止异常大响应消耗内存 |

**违规行为**：出站到非白名单 endpoint → 拒绝请求，记录 `PROVIDER_EGRESS_DENIED`，不重试。

## 3. API Key 安全管理

| 要求 | 方案 | 现状 |
|---|---|---|
| 存储 | 仅环境变量（`DEEPSEEK_API_KEY` / `OPENAI_API_KEY`），`.env` 不入库 | ✅ `provider_from_env` 只按**名**检查 |
| **内存读取** | Provider 在内存中读取密钥值用于发起 HTTP 请求（`Authorization: Bearer <key>`）；密钥值只在请求构造时短暂存在于内存 | ✅ `OpenAICompatibleProvider.__init__` 保存 `self._api_key` |
| **日志禁止** | 密钥不得出现在任何日志（包括错误日志、调试日志）；异常消息中不包含密钥值 | ✅ 现有代码未记录 key 值 |
| **Trace 禁止** | 密钥不得写入 Trace、CallTrace、DecisionRecord、Evidence | ✅ 现有设计 |
| **UI 禁止回显** | 任何 API/UI/报告禁止回显密钥；只显示"已配置/未配置" | ✅ |
| **不持久化明文副本** | 不写入文件、数据库、缓存；进程退出后内存释放 | ✅ |
| **测试隔离** | 测试套件**禁止**携带真实密钥；无密钥行为 hermetic 测试 | ✅ `test_llm_policy.py` 纪律 |
| 轮换 | 密钥轮换 = 环境变量替换 + 重启服务，无持久化副本 | ✅ |
| 最小权限 | 建议使用独立子账号/限额 key（平台侧操作，列入审批条件） | 📋 待办 |

> **注意**：`provider_from_env()` 在检查环境变量**名**是否存在时不读取值；
> 但 `OpenAICompatibleProvider` 构造时确实**读取密钥值**（存入 `self._api_key`）用于
> 发起 HTTP 请求。密钥值的生命周期 = Provider 实例的生命周期。"不读取密钥值"是
> 不准确的表述——正确的是"读取用于请求，但不记录、不回显、不持久化"。

## 4. 模型版本与 Prompt 版本记录

| 项 | 记录位置 | 说明 |
|---|---|---|
| `model_version` | 每条决策记录 + Trace | 实际返回的模型名（如 `deepseek-chat`） |
| `prompt_version` | 每条决策记录 + Trace + 哈希 | 模板版本号（如 `planner-v1`），模板变更必须升版本 |
| Prompt 内容 | **不存明文** | 只存 sha256 + 字符数（`CallTrace` 既有设计） |
| 上下文版本 | `context_version` | Context Builder 格式版本，进 prompt hash |

复核要求：任取一条真实决策，应能回答"哪个模型、哪版提示词、哪版上下文"，且无法从 Trace 还原敏感原文。

## 5. Structured Output

- 输出必须通过 `TracedClient.complete_structured` + `Draft202012Validator` 校验；
- Action Proposal schema 严格（未知字段拒绝，枚举校验，confidence ∈ [0,1]）；
- 校验失败 → 重试（≤ `max_retries`）→ 仍失败则 `StructuredOutputError`：
  **不产生决策、不伪造动作**，按 §7 降级或停止；
- 每次调用（含失败）都进 `CallTrace`（schema_ok 标记）。

### 6.1 统计

| 指标 | 来源 | 记录 |
|---|---|---|
| `prompt_tokens` / `completion_tokens` | 响应 `usage` 字段 | 每次调用入 CallTrace |

### 6.2 费用核算与上限（D8 整改：完善费用闸设计）

| 闸 | 默认值 | 行为 | 状态 |
|---|---|---|---|
| **输入 Token 上限** | `max_prompt_tokens=4096` | 超出截断 prompt（保留核心上下文） | 🆕 待审批 |
| **输出 Token 上限** | `max_output_tokens=512`（现状） | 超出截断/报错 | ✅ 现状 |
| **单次探索费用上限** | **≤ $0.50**（建议值） | 超限 → 硬停（`BUDGET_EXHAUSTED`），不再发起任何调用 | 📋 待审批 |
| **单日费用上限** | **≤ $20.00**（建议值） | 超限 → 当日全部真实调用拒绝（409 语义保持） | 📋 待审批 |
| **并发预算预留** | 并发 1（试运行阶段）；预留单次上限 × 并发数 | 防止并发探索叠加超支 | 🆕 待审批 |
| **失败重试费用** | 重试次数计入费用（每次重试消耗 token） | max_retries=2 次重试的 token 计入总费用 | 🆕 待审批 |
| **实际使用量 vs 估算使用量** | 以响应 `usage` 字段为实际值；估算值仅用于预扣 | 实际 > 估算时按实际值计费 | 🆕 |
| **价目表版本** | 配置项 `cost_per_1k_tokens`（输入/输出分列）+ `price_list_version` | 模型换代时更新并升配置版本 | 🆕 |
| **费用台账持久化** | 独立于 Trace，按日归档到 `data/llm_costs/` | 含日期、exploration_id、token、估算费用、实际费用 | 🆕 |

**关键约束**：
- **$0.50 和 $20 继续作为待审批建议值，不能视为已批准额度**；
- 上限值**只允许下调，不允许上调**（上调需重新走 D8）；
- 估算口径保守（宁可提前停，不可超支）；
- 费用台账独立于 Trace，按日归档；
- 并发预算预留 = 单次上限 × 最大并发数（试运行阶段并发=1，预留 $0.50）。

## 7. 超时、重试与失败降级

| 项 | 参数（默认） | 说明 |
|---|---|---|
| 单次调用超时 | `timeout_s=30` | 现状 |
| 重试 | `max_retries=2` | 现状；指数退避（M4 实施） |
| HTTP 5xx / 超时 | 重试后仍失败 → `LLMError` | 不伪造决策 |
| 结构化输出失败 | 重试后仍失败 → `StructuredOutputError` | 不伪造决策 |

**降级策略（默认安全停止；仅场景明确声明允许降级时才可 Real → Scripted）：**

1. `degrade: stop`（**默认**）—— 直接停止（`ERROR` / `EXECUTION_FAILED`），不猜测动作；
2. `degrade: scripted`（仅场景声明允许时）—— 回退 ScriptedProvider 兜底。

**降级标记要求**：
- 降级发生的探索，其 trace 必须标注 `degraded_from=real` + `degraded_at=<timestamp>`；
- 降级后的决策记录 `decision_source` 改为 `scripted`（不再标 `real`）；
- 报告和统计**必须**将降级后的探索与纯真实推理探索分列，不得混入真实推理成绩；
- `may_contain_real_inference` 在降级后翻转为 `False`。

红线：模型失败**绝不**产生"看起来合理"的伪造决策。

## 8. 决策记录（审计）

每次真实调用记录（`CallTrace` + DecisionRecord，见台账 §9-E）：

- decision_id / proposed_action 全文（脱敏后）/ policy_decision / execution_result；
- prompt_sha256 / response_sha256 / token / latency / attempts / schema_ok；
- model_version / prompt_version / context_version；
- cost（本次估算）与累计费用。

复核语义：真实决策**可复核**（人工审计上下文与理由），**不假装可重放**（模型随机输出不可字面复现）。

## 9. 敏感数据脱敏（D8 整改：扩展隐私清单）

### 9.1 禁止进入模型上下文的数据类型

| 数据类型 | 处理 | 来源 |
|---|---|---|
| 密码/凭据 | 只从受信配置注入动作参数；trace/日志/prompt 全链路脱敏（`redact_actions` 既有） | 表单输入 |
| **Token / API Key** | 禁止进入 prompt / trace / 日志；只在 Provider HTTP 请求头使用 | 环境变量 |
| **Cookie** | 禁止进入 prompt / trace；session cookie 不得出现在 Observation 或上下文中 | 浏览器 |
| **Authorization 头** | 禁止进入 prompt / trace；只在 Provider 请求中使用 | HTTP |
| **邮箱、电话等 PII** | prompt 中的页面文本需经 PII 过滤（正则匹配邮箱/手机号模式 → REDACTED） | 页面文本 |
| **URL 查询参数** | Observation 中的 `href` 只保留路径部分（去 query/hash）；完整 URL 的 query 参数不进 prompt | DOM 属性 |
| **页面中意外出现的敏感字段** | `SENSITIVE_HINT` 匹配（password/token/secret/key/credential 等）→ REDACTED | 页面文本/DOM |
| 表单输入值 | **从不采集**（红线：密码不是 observation） | DOM input |
| GT / 审计数据 | 不进 prompt、不进 trace | Benchmark |
| 内部路径/密钥 | 错误消息过滤（既有纪律） | 系统 |

### 9.2 允许进入模型上下文的数据类型

| 数据类型 | 说明 |
|---|---|
| 脱敏后的页面 URL 路径 | `url_path`（无 query 参数） |
| 页面标题 | `title`（≤120 字符，经敏感词过滤） |
| 可见 testid 列表 | `visible_testids` |
| 元素结构摘要 | `visible_elements`（tag/testid/name ≤60 字/visible/disabled，无 value） |
| 计数/关系 | `dom_counts` / `dom_relations`（结构化数据，非文本） |
| 脱敏后的 text_excerpt | 经 PII + 敏感词双重过滤后的页面文本片段 |
| TestIntent | goal/target/expected_outcomes/constraints（用户声明的测试意图） |
| 历史动作（脱敏后） | `action_sequence`（REDACTED 标记） |
| 预算状态 | 剩余步数/时长/工具调用/费用 |

### 9.3 试运行数据范围

- **当前仅本地批准的 TeamFlow 测试环境**可以作为首轮试运行对象；
- 不得将外部网站、生产环境数据发送给模型；
- TeamFlow 测试数据本身不含真实用户信息（测试账号 `tester` / 测试项目均为虚构）。

## 10. 人工启用开关（Kill Switch）（D8 整改：如实描述现状）

| 项 | 设计 | 现状 |
|---|---|---|
| 默认状态 | **关闭**（`llm` 策略 409 BLOCKED 保持） | ✅ 当前实现 |
| **谁可以开启** | 仅运维/负责人通过环境变量 `TG_REAL_LLM=1` + 重启服务 | 📋 待审批 |
| **谁可以关闭** | 同上（环境变量 `TG_REAL_LLM=0` + 重启服务）；紧急情况任何发现异常的人员可触发 | 📋 待审批 |
| **关闭后的生效时间** | **需重启服务**（当前实现无运行时热切换） | ⚠️ 如实描述 |
| **进行中的请求** | 重启后进行中的 HTTP 请求被中断；已在 Provider 侧发起的调用可能完成但结果不被采纳 | ⚠️ 如实描述 |
| **已返回但尚未执行的模型结果** | 重启后丢弃（不缓存决策）；已持久化的 Trace 保留（审计） | 📋 待审批 |
| **关闭后恢复 Scripted 路径** | 重启后 `llm` 策略恢复 409 BLOCKED；`scripted` / `scripted-agent` 路径不受影响 | ✅ 当前实现 |
| 运行时开关 | **当前不具备一键运行时控制能力**——只能通过环境变量 + 重启服务 | ⚠️ 如实描述 |
| 关闭后残留 | 无状态残留（无缓存决策复用）；已产生的真实决策 trace 保留（审计） | ✅ |
| 应急 | 出现费用异常/危险动作趋势 → 先关开关（重启服务），再分析 trace | 📋 |

> **如实声明**：当前 Kill Switch 的实现是环境变量 + 重启服务，**不具备**运行时一键热切换能力。
> 运行时热切换（如管理 API 触发、信号量控制）列为 M4 可选增强项，不在本轮承诺。
> 不得宣称已有一键运行时控制能力。

## 11. 风险与回滚方案

### 11.1 风险清单（D8 视角）

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| D1 | 费用失控 | 中 | 单次/单日硬闸 + 独立限额 key + 费用台账 |
| D2 | 模型幻觉导致危险动作 | 中 | 单通道执行 + 六项执行前检查 + denied_actions |
| D3 | 幻觉 claim（假成功） | 中 | 模型永不裁决 verdict；断言独立求值 |
| D4 | 敏感数据外发 | 低 | 全链路脱敏 + 不采集输入值 + prompt 只发观测 |
| D5 | 三模式混淆 | 低 | is_real_model 硬标记 + UI 强展示 + 验收断言 |
| D6 | 供应商不可用 | 低 | 超时/重试/降级；不影响 Scripted 路径 |
| D7 | 审计断链 | 低 | decision_id 链 + Trace Hash v3 + CallTrace 全量 |

### 11.2 回滚方案

| 触发 | 回滚动作 | 生效时间 | 影响面 |
|---|---|---|---|
| 费用异常 | 关闭开关 | 下一决策环 | 仅真实推理停用 |
| 危险动作趋势 | 关闭开关 + 复盘 trace | 立即 | 同上 |
| 模型输出质量问题 | 降级 scripted / 关闭 | 立即 | 同上 |
| 密钥泄露 | 轮换密钥 + 关闭开关 | 立即 | 无持久化副本需清理 |
