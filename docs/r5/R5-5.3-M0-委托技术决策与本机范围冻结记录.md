| D1 | 有限采用目标准入：每条路径声明 `expected_goal_status`，且全部 required expect 通过才允许编译。 | 正向要求目标 VERIFIED；负向允许预期 NOT_VERIFIED、独立断言全 PASSED 的候选；INCONCLUSIVE 不得通过；Agent 不设置 TestCaseVerdict。 |

## 3. 本机开发边界

- 仅本机 loopback、单用户、单进程和单 Worker；不得远程访问或多用户部署。
- 不修改 C05/C06/C11/C12，不修改 Ground Truth、Oracle 或 OriginPolicy，不清空正式数据。
- 所有浏览器操作继续经 ToolGateway；Candidate/Repair 仍需人工操作，Agent 不可批准或晋升。
- 不启用真实 LLM、不新增真实请求路径；`llm` 策略保持 **409 BLOCKED**，请求数为 **0**。M4 状态为 `NOT_RUN`，真实推理指标为 `None(BLOCKED)`。
- M1-0 是首个工程任务；部署安全边界通过前不得开始其他 M1 业务开发。M1、M2、M3、M5 均按阶段验收门槛顺序推进。

## 4. M1 本机准入和后续门禁

本机范围授权已满足当前 M1 总体准入。具体实施仍须先完成 M1-0 并通过其负向测试；之后按 M1-1～M1-9 顺序落实数据模型、版本注册表、Digest、数据租约、真实 SUT 场景、审批治理修复和联合验收。M1 未 PASS 不进入 M2，M2 未 PASS 不进入 M3，M1～M3 未完成不进入 M5 综合验收。

`M0_FROZEN=false` 仍准确描述跨角色治理状态，不阻止此处已授权的本机范围内开发。任何远程/多用户部署、企业级审批声明、真实模型调用、C05 治理状态变更，均超出本授权范围。

## 5. D8 独立门禁

D8 控制真实模型调用及其费用、隐私、Provider 和 Kill Switch 风险；本机 Scripted/Mock 开发不需要真实模型服务，因此 D8 不阻止 M1～M3 或 M5 受限验收，但始终阻止 M4 真实 LLM。材料准备、正式提交/受理、正式批准是不同状态。本轮没有正式批准证据，故继续保持 `409 BLOCKED`，不得发起调用。
