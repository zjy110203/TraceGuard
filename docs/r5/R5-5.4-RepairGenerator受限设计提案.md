# R5-5.4 Repair Candidate Generator 受限设计提案

状态：设计提案 / 需要人工批准；本轮未实现自动 Generator、未新增生成 API。现有冻结规格未定义 Diagnosis → 自动修改资产的生成规则与权威语义匹配证据。用户要求超范围先提案，因此不将人工 Locator 编辑描述为自动生成。

## 建议批准的最小范围

只允许确定性 locator_update：复用现有 create_repair 的真实 Run → Diagnosis → SUPPORTED/CONFIRMED hypothesis → supporting evidence 包含性校验；进一步验证 Evidence 内容/摘要/时效、正式 Case 的 base version/digest、Oracle 和全部 required assertions。提取校验函数时须保持原创建 API 行为。

只有权威语义关联（例如受控应用版本映射或显式稳定语义键）能将旧 Locator 和新 Locator 联系起来，且唯一匹配，才产生候选。仅 DOM 出现、相似文案或单个元素不是足够证据。多个匹配、证据不足、缺少可信映射均返回 NEEDS_HUMAN_INPUT / INCONCLUSIVE，不猜测。

输出应携带 Candidate、Diff、change_kinds、理由、hypothesis/diagnosis/run/evidence、before/after、风险、不确定性、base version/digest、generator version。每次保存前重新执行 CAS/Oracle/required assertions 保护。

流转：建议 → 人工选择保存 DRAFT → Validation → PENDING_APPROVAL → Human Approval → Sandbox Replay → Human Promotion → Regression。禁止直接写正式文件、批准、晋升、回滚及 Oracle/断言变更。无真实 LLM。

## 必须先确认

项目方确认 locator_update 的可信语义映射来源、允许的证据时效和新建议接口/持久化字段后，才能实施。wait_condition、test_step_fix 等本轮仅研究，不默认为已批准生成规则。

验收须覆盖唯一可信映射、歧义、错误 hypothesis/evidence、篡改/过期、base/Oracle/assertion 改变、无批准/晋升权限及正式资产不变。当前这些 Generator 专项为 NOT_RUN，因为 Generator 未实现。

## 本轮可执行的工作台改进

复用现有 Diagnosis API 加载受支持假设，自动填 supporting evidence；提供人工 Locator 编辑，保持高级 JSON 入口；基于加载资产构造下一版本与 Diff，继续由原后端验证。切换 Case 后清空已加载资产，避免错误来源。此功能不作证据充分性或自动修复能力声明。
