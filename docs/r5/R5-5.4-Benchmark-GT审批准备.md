## 新增离线 append-only 导入准备

`python -m benchmark.gt_import decision.json --root <隔离GT目录> --version gt-v2`。

decision 包含 decision=APPROVED、具名 reviewer、approval_record、带时区 approved_at、base_version、base_sha256、records。每行严格只含 scenario_id、primary_cause、fault_class、authority_ref；必须完整且无重复地覆盖 base。支持明确的机制词表 API/NETWORK/PERSISTENCE/UI_RENDERING/TIMING/NONE；其他分类须先确认口径。不可修改 expected_verdict 或其他原字段。

base_sha256 使用原 GT envelope payload 的既有 sort_keys JSON 摘要算法。先校验全部行、base 摘要和批准，再原子写入新版本；同名拒绝。审批原文进入新 payload。导入不激活 live 评测、不改变旧版本选择，不自动解除任何 BLOCKED。若正式批准后需要评测启用，另须显式选择 GT 版本和对应 Dataset，避免静默混合。

当前仅用 synthetic-case 的临时目录测试严格校验；这不构成五行真实映射批准。primary_cause_accuracy / selective_accuracy / macro_f1 继续 null/BLOCKED。D8 未批准，M4 NOT_RUN/409 BLOCKED，真实 LLM 请求数 0。


## 评测激活设计核对（待批准）

当前 BenchmarkStore.restore 按排序遍历全部 GT 文件，对相同 scenario_id 取首条。GroundTruthManager.version 固定为 gt-v1。DatasetManager.create 从当前 manager 的版本和场景列表生成 dataset.version，restore 会重新创建 Dataset。因此将 v2 文件放进目录并不能证明某次实验使用了 v2。

拟议准入步骤如下。

1. 由批准记录显式指定 gt_version、GT envelope 的 payload SHA-256 和新 Dataset 版本。导入与激活分别审批，不提供 latest 或目录顺序回退。
2. 按版本和摘要打开唯一的不可变 GT envelope，复核基线、审批信息、场景覆盖和摘要。按选定版本创建隔离的 GroundTruthManager，存储键为 (version, scenario_id)。重复场景、版本缺失或摘要不符时中止。
3. 新建不可变 Dataset manifest，绑定 dataset_id、dataset_version、gt_version、gt_sha256、分区和有序场景集合。恢复时按 manifest 精确装载，禁止用活动 manager 重算历史版本。旧实验继续使用原版本。实验结果记录两个版本及摘要。
4. 所有版本追加发布，同名写入须原子拒绝。验收需覆盖 v1/v2 启动顺序、同 ID 不同标签、重启、旧 Dataset 回放、摘要损坏和未审批选择。运行后复核两个历史 envelope 的原始字节摘要。
5. 真值映射和激活任一未批准时维持 BLOCKED，真实归因指标仍为 null。本轮仅复核设计。
