## 2. 关键设计落点

### 2.1 为什么不新建 EventStore

`events.py` 已经有幂等键唯一约束、`(producer_instance_id, sequence)` 唯一约束、受信 `workspace_id` 注入。
本层只补"数据库权威的全局顺序"，其余全部复用。写入唯一入口是 `EventStore.append_stream`。

### 2.2 两个序号：持久位置 sequence 与投递序 delivery_seq（审查后修订）

`append_stream` 在同一事务里先插入游标行（`AUTOINCREMENT`），把拿到的 `stream_seq` 作为已落库事件的
`RunEvent.sequence`。`sequence` 现在是 `int | None`：**`None` 表示该事件从未落库**（写库失败），
不再用本地计数器冒充持久号段。投递顺序另由 `delivery_seq`（进程内、每条事件都推进）承担，
驱动 SSE 排序与缺口检测。原报告"三者一致"仅在写入成功时成立；失败路径的号段冲突见 §6.1。

迁移兼容：`ev_stream_state.pruned_through` 是水位；旧行没有游标行时 `backfill_stream_cursors()` 按
`(observed_at, sequence, event_id)` 补一次并返回条数（启动日志可见），不是静默跳过。

### 2.3 游标与 Last-Event-ID

- 持久模式且写入成功：`id: v2:<stream_seq>:<producer_instance_id>`（3 段）；持久模式但写库失败：
  **不发 `id:` 行**（客户端保留上一个可证明的持久点）；内存模式仍是 `id: <event_id>`（行为不变）。
- 服务端两种格式都接受：`v2:` 需通过格式/实例归属/水位/越界/位置实例绑定/存在性六重校验；
  `runevt_…` 查游标表。合法历史实例必须接受，跨库同号必须通过实例归属拒绝。
- 未知游标：**不再从 0 全量重放**（旧行为会重复投递整段历史），改为发 `stream.notice{code:"cursor-unknown"}` 并从当前末尾只推新事件。
- 过期游标（`stream_seq <= pruned_through`）：发 `cursor-expired`，回放仍保留的历史。
- 这是**行为变更**，已在设计文档 §7/§11、decision D-R5-511-3 与本报告登记；前端同步支持。
- **唯一正式协议以设计文档 §7 为准**（旧文稿"发送端不改 event_id / v2 为 4 段"的描述已作废）。

### 2.4 四类"缺口"分开报告

| 场景 | 信号 |
|---|---|
| 订阅队列溢出 | `: gap from=.. to=.. dropped=N`（保留，兼容旧客户端）+ `stream.notice{code:"gap"}` |
| 保留窗口裁剪 | `stream.notice{code:"cursor-expired"}` |
| 游标不认识 | `stream.notice{code:"cursor-unknown"}` |
| 写库失败 | `stream.notice{code:"persist-degraded"}` + `/events/durability` |

`stream.notice` 是 SSE 传输层控制事件，**不是** `RunEvent`，C05 字段一个未动。

### 2.5 写入失败不伪造成功

- `degrade`（API 默认）：事件照常实时投递（执行不能被观测设施拖死），但 `sequence=None`、不发 `id:` 行、
  `durability_state.mode=degraded`（仅在失败未恢复时）、`failures` 计数、`undurable_*_delivery` 记录不可回溯区间；
  `first_undurable_sequence` 保留为**投递序号**的弃用别名；前端显示"不可回溯"；**事后不回填**。
- `strict`（测试/门禁用）：直接抛错，调用方看到真实失败，且不推进 `delivery_seq`、不产生 wire 事件。
- 测试 `test_failed_write_degrades_and_is_never_reported_as_durable` 同时断言：事件进了内存历史、`replay_after(0)` 为空。

### 3.4 浏览器门禁发现并修复的真实缺陷（#2）

浏览器验收首跑 141/150 失败：`overview: no metric button found`，截图显示页面永久停在"加载中…"，
而服务端日志无错误、接口单测直连 200（52 ms）。用 `faulthandler` 抓栈发现事件循环处于空闲，
真正原因是 **SSE 回放循环把事件循环卡死**，浏览器所有请求排队等不到响应。

根因：回放用"事件自身 `sequence`"推进游标，而查询用"持久位置 `stream_seq`"过滤。
`chain_api` 通过 `EventStore.append` 写入证据事件（`sequence` 是每 Run 的小序号），
它们的 `stream_seq` 由迁移补齐后与 `sequence` 不等；SSE 回放这类行时 `last_seq` 不前进，
同一个批次被无限重读 —— 一个同步循环卡在 async 生成器里，整个进程其他请求全部饿死。

修复（三处，缺一不可）：

1. `EventStore.replay_stream(..., producer_id=)`：run 事件流只回放 `traceguard.eventbus` 生产的行，
   证据事件由 `/evidence/events` 提供，两套序号空间不再混在一条流里；
2. `RunEventRecorder.replay_page()` / `EventBus.replay_page()` 返回"本页到达的位置"，回放按**位置**推进；
3. SSE 循环加"无进展即中止并记录 `sse_replay_no_progress`"的防御，杜绝再次出现同类死循环。

回归：`test_replay_page_advances_by_position_not_by_event_sequence`（构造 sequence=1/position=3 的行，
断言下一跳为空且不重复投递）、`test_replay_ignores_other_producers_events`。
修复后浏览器门禁 **150/150 PASS（0 skipped）**。

> 这条缺陷是"验收门禁真的在验证产品"的证据：单元测试全绿时它依然存在，只有真实浏览器 + 真实数据才暴露。

### 3.5 同一次修复引入的二次缺陷（自查发现并修复）

加上"无进展即中止"的防御后，`tests/e2e/test_user_journey.py` 两项超时。原因是防御写错了位置：
**空批次（没有历史可回放）本来是正常的结束条件**，却被当成"卡死"直接 `break`，导致流在回放阶段就结束，
之后既没有实时事件也没有重连。修复为：空批次 → 正常进入实时阶段；只有"非空批次且位置不前进"才算卡死。
这正是"先加防线、再用测试验证防线本身"的必要性——防御逻辑也会伤人。

### 3.6 迁移（schema 变更已登记）

两张游标表属于**平台 schema**，必须进迁移链，否则 `alembic upgrade head` 出来的库与新建库不一致，
回放只在"升级过的环境"里坏。因此：

- `packages/core/metadata.py`：`PLATFORM_TABLES` 从 10 张增至 12 张（新增 `ev_stream_cursor` / `ev_stream_state`）；
- 新增迁移 `alembic/versions/7c1a4e2b9f31_add_event_stream_cursor.py`（可 downgrade，只丢顺序索引，不丢事件）；
- `tests/test_migrations.py`：表数量断言更新为 12；顺带修正一处**空断言**——原用例依赖"恰好有别的表注册"
  才通过，现在显式导入 TeamFlow 模型，真正校验 `tf_*`/`eval_*` 不进平台迁移。

## 5. 已知限制

1. SQLite 单写者，写入串行化；未引入外部 broker（未批准）。
2. `stream_seq` 由单库自增，不做跨库全局唯一承诺。
3. `degrade` 期间的事件不可回溯（设计选择）。
4. 保留窗口按条数（默认 20000），不按时间。
5. `cursor-unknown` 不再全量重放（行为变更，已登记）。
6. 旧 v2 事件（R5-4.10 写入，无游标行）在首次启动时被补游标，顺序按 `(observed_at, sequence)` —— 这是唯一仍使用
   `observed_at` 的地方，且只在迁移时发生一次，之后回放顺序稳定。

## 7. 长稳与保留窗口独立测试计划（P2，非本轮阻塞项）

| 编号 | 场景 | 方法 | 判定 |

| S-1 | 30 分钟持续运行 | 后台持续 publish + 定时 SSE 订阅，记录 `dropped_total`/延迟 | 无静默丢失；所有 gap 有对应 notice |
