## 1. Scenario Registry（🔧 扩展）

**模块**：`packages/agents/scenarios.py`（保持唯一注册点；Explorer 核心零场景分支）。

### 1.1 输入

| 参数 | 类型 | 说明 |
|---|---|---|
| `scenario` | `Scenario`（frozen dataclass） | 场景包实例，字段见设计 §2.2 |
| （新增）`version` | `str` | SemVer；与 `scenario_id` 组成唯一键 |
| （新增）`preconditions` / `data_setup` / `cleanup` / `denied_actions` / `paths.*` | 结构化字段 | 见数据契约 §A |

### 1.2 输出

| 返回 | 说明 |
|---|---|
| `register()` → `Scenario` | 注册成功返回；失败抛 `ValueError`；`(scenario_id, version)` 查重 |
| `require(id, version)` → `Scenario` | 精确版本取用；执行时锁定并写入 Trace |
| `require(id)` → `Scenario` | 不指定版本时取最高 SemVer（latest）；兼容旧调用 |
| `all()` / `implemented()` → `tuple[Scenario, ...]` | 查询 |
| `public_view()` → `dict[str, str]` | 兼容旧客户端（id → description），形状不变 |
| `versions_view()` → `dict[str, list[str]]` | 🆕 id → 版本列表（供新客户端选择精确版本） |
| `validate_all()` → `dict[str, list[str]]` | 问题清单（空 = 全部合法） |

### 1.3 依赖

`goal_assertions.validate_assertion`（断言定义校验）、`KNOWN_ACTIONS`（工具白名单）。

### 1.4 权限

- 注册操作仅限进程内构建期（`build_default_registry` / 测试装配），**不暴露远程注册 API**；
- 远程侧只有读（`GET /explorations/policies` 暴露意图模板），保持现状。

### 1.5 错误处理

| 情况 | 行为 |
|---|---|
| 结构非法（空字段/非法 origin/未知工具/空 constraints…） | `ValueError`，拒绝注册 |
| `(scenario_id, version)` 重复 | `ValueError`，不静默覆盖 |
| `implemented=True` 但 `paths.normal` 为空 | 拒绝注册 |
| `denied_actions ∩ allowed_actions ≠ ∅` | 拒绝注册 |
| path 缺 `expected_goal_status` 或 `expect`（DR2-01） | 拒绝注册（定义错误） |
| `expected_goal_status` ∉ {`VERIFIED`, `NOT_VERIFIED`}（DR2.1-01） | 拒绝注册（不允许把 `INCONCLUSIVE`/`NOT_EVALUATED` 写成预期） |
| `expect` 为空数组（DR2.1-01） | 拒绝注册 |
| `expect` 全部 `required=false`（无任何 required 独立证据，DR2.1-01） | 拒绝注册 |
| 路径声明中出现 `test_case_verdict` 字段（DR2.1-01） | 拒绝注册（裁决权不在声明方） |
| `secret_refs` 引用未声明/跨场景/含路径穿越（DR2.1-02） | 拒绝注册 |
| `secret_refs` 命名空间非法（DR2-03） | 拒绝注册 |
| 同版本 `scenario_digest` 不一致（DR2-06） | `SCENARIO_DIGEST_MISMATCH`，拒绝注册 |
| 未实现场景被执行 | API 返回 `UNSUPPORTED_SCENARIO` + `blocked_reason`（现状语义保持） |

### 1.6 测试要求

- 注册表校验参数化（每条 validate 规则一个用例）；
- 版本并存：同 id 不同 version 可注册、同 id 同 version 拒绝；
- 四类路径（正常/异常/边界/恢复）步骤工具越界 → 拒绝；
- 回归：现有 26 项定义层用例全过（不降断言）。

### 1.7 版本兼容性

- `to_dict()` 只增字段不改不删；旧客户端忽略新增字段；
- `public_view()` 形状不变（`dict[str, str]`）；
- `versions_view()` 为新增方法，旧客户端不调用不受影响；
- `RunExplorationRequest.scenario_version` 为可选字段（默认空字符串），旧客户端不传时自动解析为最新版本；
- 旧 Trace 中的 `scenario_id` 无 `scenario_version` 时标记 `legacy-unversioned`
  （**不**按最低/最新版本伪造历史解释，DR2-06）；
- 请求不存在的版本 → `UNSUPPORTED_SCENARIO_VERSION` + `available_versions`（明确错误，不静默回退）；
- Digest 不匹配 → `SCENARIO_DIGEST_MISMATCH`（与版本不存在是不同错误语义）。

## 2. Context Builder（🆕 新增）

**模块**：`packages/agents/context_builder.py`（新建，职责单一）。

### 2.1 输入

| 参数 | 来源 | 说明 |
|---|---|---|
| `intent` | C01 TestIntent | goal / target / expected_outcomes / constraints |
| `observation` | `Observation v2` | 当前页面结构化观测 |
| `history` | `ExplorationTrace` | 历史 Action + 结果（已脱敏） |
| `budget_state` | `Budget` | 剩余步数/时长/工具调用/（M4）费用 |
| `goal_state` | `GoalEvaluator` 最近结论 | 当前目标状态 |
| `scenario` | `Scenario` | allowed/denied_actions、constraints、paths |

### 2.2 输出

`DecisionContext`（结构化 dict / dataclass）：组装后的模型输入上下文，
含各来源的规范化字段与 `context_version`。

### 2.3 依赖

`exploration.intent_of`（意图规范化）、`sanitize_action`（历史动作脱敏）、Observation v2 读取器。

### 2.4 权限

只读；**不得**读取输入值/凭据明文（凭据仅在动作参数替换时来自受信配置，不进上下文）；
prompt 组装时对 password/敏感 selector value 做脱敏替换（复用 `redact_actions`）。

### 2.5 错误处理

| 情况 | 行为 |
|---|---|
| 观测缺失 | 上下文标记 `observation_missing`，Planner 只能输出 snapshot/navigate 类恢复动作 |
| 历史为空 | 正常（首步） |
| 场景缺失 | 拒绝构建（探索必须绑定场景） |

### 2.6 测试要求

- 确定性：相同输入 → 相同上下文（字节级稳定，便于 prompt hash）；
- 脱敏断言：上下文任何字段不得含明文密码；
- 字段完整性：7 类输入各有对应输出字段。

### 2.7 版本兼容性

`context_version` 进入 Trace 与 prompt hash；上下文格式变更升版本号，旧版本可复算（存 raw 输入引用）。

## 3. Agent Planner（🔧 扩展）

**模块**：`packages/agents/exploration.py`（`Policy` Protocol）+ `scripted_agent.py` +（M4）真实策略。

### 3.1 输入

`DecisionContext`（§2 输出）。

### 3.2 输出

`Action Proposal`（结构化，见数据契约 §B）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `decision_id` | ✅ | `dec_<uuid>` |
| `action` | ✅ | ∈ KNOWN_ACTIONS |
| `arguments` | ✅ | 结构化参数（selector/url/value…） |
| `rationale` | ✅ | 决策理由（人类可读，进 trace） |
| `expected_effect` | ✅ | 预期页面变化（执行后比对） |
| `confidence` | ✅ | 0~1，仅审计，不作放行依据 |
| `prompt_version` / `model_version` | 真实阶段 ✅ | Scripted/Mock 用 NOT-REAL 标记 |

**空决策**（`None`）合法：Planner 判定无动作可做 → 停止（`PLAN_EXHAUSTED` 或 `POLICY_STOP`）。

### 3.3 依赖

LLM Provider（§8）或 Scripted 脚本；Context Builder；`ToolCall` 既有结构。

### 3.4 权限

- Planner **只能产出提案**，不能执行；执行唯一入口是 ToolGateway；
- 不能声明 GOAL_VERIFIED（verdict 只属于 Goal Evaluator）；
- 不能声明 TestCaseVerdict（测试用例裁决只属于独立证据断言求值，DR2-01）；
- 敏感输入只能提交 `secret_ref`，不能提交明文 `value`（DR2-03）；
- 不能读取 GT（Benchmark GT 隔离红线）。

### 3.5 错误处理

| 情况 | 行为 |
|---|---|
| Structured Output 不合法 | `StructuredOutputError`，不产生决策；按 §5.4 降级或停止 |
| Provider 不可用 | `ProviderUnavailable`，探索报 LLM unavailable（不静默换脚本冒充） |
| 提案违反 schema（未知字段/类型错） | 拒绝提案，记 `policy_decision=invalid-proposal` |
| Scripted 脚本耗尽 | `PLAN_EXHAUSTED`（现状语义） |

### 3.6 测试要求

- Proposal schema 参数化校验（合法/非法字段矩阵）；
- 重复/危险动作检测（同参数连续 2 次 → POLICY_STOP）；
- MockProvider 闭环：观测变化 → 提案变化（决策确实"看"了页面）；
- 回归：现有 `test_scripted_agent.py` / `test_planner.py` / `test_llm_exploration.py` 全过。

### 3.7 版本兼容性

- `Policy.next_action(observation) -> ToolCall | None` 旧签名保留为兼容视图，
  新代码走 `propose(context) -> ActionProposal | None`；
- `agent_version` 命名规范保持（含 `-NOT-LLM` / `-NOT-REAL-INFERENCE` 后缀纪律）；
- Trace Hash v3 覆盖 proposal 全字段；v2/v1 记录按旧规则校验。

## 4. Policy Validator（🔧 扩展）

**模块**：独立校验模块（前置于 ToolGateway），对应设计 §4.3 六项检查中的策略层部分。

**职责分离（DR1-04 明确）**：
- PolicyValidator 负责**策略层**检查（Proposal schema、场景约束、重复/危险检测）；
- ToolGateway 负责**安全层**检查（URL/selector/value/预算权威校验）；
- 两层各自独立、不交叉，避免重复校验导致规则不一致；
- PolicyValidator **不执行浏览器操作**，只输出 PolicyDecision。

### 4.1 输入

| 参数 | 说明 |
|---|---|
| `proposal` | Action Proposal |
| `scenario` | allowed/denied_actions、constraints |
| `budget_state` | 剩余预算 |
| `history` | 重复/危险检测用 |

### 4.2 输出

`PolicyDecision`（结构化）：`allowed: bool` + `reason_code` + `detail`；
reason_code ∈ `ok / unknown-action / not-allowed-by-scenario / origin-denied /
denied-action / budget-exceeded / duplicate-or-dangerous / invalid-proposal /
invalid-authorization / forged-decision / args-mismatch / cross-run-token / token-replayed /
unauthorized-secret-ref / destructive-not-authorized`。

**放行时附带执行授权凭证（DR2-02）**：
- `allowed=true` 时签发 `authorization_token`（HMAC 签名），绑定 run_id / decision_id /
  scenario_id / scenario_version / action / args_digest / budget_state_version / nonce / expires_at；
- 凭证一次性（nonce 消费后作废）；
- **签发侧与消费侧的原子性契约由 §5.4 统一规定（DR2.1-03）**：nonce 原子消费、预算预留在同一
  临界区完成版本比对、同 Run 串行执行——签发方不得假定"消费侧会自己处理并发"；
- ToolGateway 执行前必须验证凭证（6 项，见 §5）；
- 拒绝不签发凭证。

### 4.3 依赖

`OriginPolicy`/`Budget`（exploration.py）、场景约束、历史动作记录。

### 4.4 权限

安全边界执行者：**任何检查失败都不得放行**；`origin-denied` 额外触发 `POLICY_STOP`
（越界一次即停，不给重试机会）。禁止用配置放宽 OriginPolicy。

### 4.5 错误处理

- 检查自身异常（如预算状态缺失）→ 拒绝放行（fail-closed），记 `invalid-proposal`；
- 不吞异常：校验器崩溃必须让探索以 `ERROR`/`EXECUTION_FAILED` 停止，不静默继续。

### 4.6 测试要求

- 六项检查逐项用例（含边界：允许 origin 带端口精确比对）；
- fail-closed 用例（校验器异常 → 不放行）；
- 回归：`test_explorer_security.py` / `test_network_gateway.py` / `test_security_r4.py` 全过。

### 4.7 版本兼容性

`PolicyDecision` 为新增记录结构，进 Trace（`policy_decision` 字段）；
不改变既有 `ToolGateway.authorize` 抛错语义（拒绝仍是异常/返回码双通道中的一种，实施时保持现状签名）。

## 5. ToolGateway（🔧 最小扩展）

**模块**：`packages/agents/exploration.py`（`ToolGateway` / `ToolSpec` / `Budget`）。

**权威地位（DR1-04 明确）**：
- **唯一执行授权入口**——模型、脚本、Planner 都不得绕过；
- 对 URL、selector、value、预算进行**最终校验**（权威安全检查）；
- 即使 PolicyValidator 放行，ToolGateway 仍可拒绝（最终防线）；
- **不允许 Planner 绕过**。

### 5.1 输入

`ToolCall`（tool + args）；`Budget` 状态；**执行授权凭证（DR2-02）**。

### 5.2 输出

授权通过 → `PlaywrightAdapter.execute` 结果 dict；拒绝 → 抛错/拒绝记录（现状）。

### 5.3 依赖

`UrlGuard` / OriginPolicy / selector 与 value 安全检查（现状 `_check_url/_check_selector/_check_value`）；
**Secret Resolver（DR2-03）**：`secret_ref` 解析为真实值（仅执行阶段注入）。

### 5.4 权限

- 浏览器执行**唯一通道**（模型与脚本都不得绕过）；
- URL 校验现状语义不变（SSRF/DNS rebinding/redirect 防护不动）；
- **执行前必须验证授权凭证（6 项，DR2-02）**：
  ① 凭证来自受信 PolicyValidator（HMAC 验证）；② 属于当前 Run；③ Action 与 args_digest 一致；
  ④ Scenario Version 一致；⑤ 未过期、未重复消费（nonce）；⑥ 预算状态版本未变。
  任何一项失败 → 拒绝（`invalid-authorization`），不放行；
- **原子性（DR2.1-03，设计 §4.3 唯一权威）**：
  - 同一 `run_id` 的 Action **串行执行**（`run_lock`），首期不支持并发动作；
  - `nonce` 消费原子化：`consume(nonce) -> bool` 单次原子操作，唯一约束/临界区 CAS，
    只有返回 `true` 的一方才可执行；同一凭证并发提交**只允许一个成功**；
  - 预算检查与预留**不可分离**：`reserve(cost, expected_budget_version)` 在同一临界区内
    完成版本比对与扣减，版本不符 → `budget-state-changed`（要求重新决策，不静默重签）；
  - 固定顺序 `verify → reserve → execute`，**禁止先执行后补验**；
  - `args_digest` 覆盖完整 Action 与全部实际参数（含 `secret_ref` / `value_ref` 字面量），
    摘要**在秘密解析之前**计算（轮换不改摘要）；
  - HMAC 密钥仅服务端持有，不落 Trace/日志/错误；轮换用双密钥并行验证窗口，支持紧急失效；
- **secret_ref 解析仅在执行阶段**：真实值不进模型上下文、不进 Trace、不进日志/错误（DR2-03）；
- 不削弱现有 ToolGateway 和 OriginPolicy（凭证是增加一层，不替代）。

### 5.5 错误处理

预算超限 → `STEP_BUDGET` / `TIME_BUDGET` / `TOOL_CALL_BUDGET`（现状）；
（M4 新增）费用超限 → 聚合语义 `BUDGET_EXHAUSTED`（记录沿用细分值）。

### 5.6 测试要求

- 现有 `test_explorer_security.py` 预算/工具矩阵回归；
- 费用闸用例（M4）：单次上限、单日上限、累计记账；
- **授权凭证原子性六类用例（DR2.1-03，缺一不算完成）**：同一 nonce 并发（恰好 1 成功 +
  1 `token-replayed`）、同 Run 两 Proposal 竞争预算（1 成功 + 1 `budget-state-changed`）、
  参数被修改后执行（`args-mismatch`，含追加参数/换 selector/换 `secret_ref`）、
  授权过期（`token-expired`）、预算版本变化（`budget-state-changed`）、
  直接调用执行入口（`invalid-authorization` / `forged-decision`）；
- **敏感输入识别用例（DR2.1-02）**：`input[type=password]` 命中、`autocomplete` 敏感值命中、
  场景 `sensitive_selectors` 命中、`unknown` → fail-closed、明文 value 拒绝（含空串）、
  跨场景引用拒绝、`env://` 与 `..` 路径穿越拒绝。

### 5.7 版本兼容性

`ToolSpec` / `Budget` 字段只增不改；`tool_version` 保持 `1.0.0` 语义（工具集合无删减）。

### 5.8 Secret Resolver（DR2.1-02：独立受信组件）

**模块**：新建（M3 落地），仅被 ToolGateway 在执行阶段调用；模型、Planner、Context Builder
均不可直接调用。

| 项 | 内容 |
|---|---|
| **输入** | `secret_ref`（原始字符串）、`scenario`（`scenario_id` + `secret_refs`）、`run_id`、`step_id` |
| **输出** | `ResolvedSecret{ value, source, secret_name, digest_prefix, resolved_at }`；`value` 在 `repr`/`to_dict` 中恒为 `REDACTED` |
| **权限校验** | ① 语法：`^secret://{scenario_id}/{name}$`，`name` ∈ `^[a-z0-9][a-z0-9_-]{0,63}$`；② 命名空间归属：ref 的 `scenario_id` == 当前 scenario；③ 集合成员：ref ∈ `scenario.secret_refs`；④ 来源受限：仅受信后端（环境变量白名单前缀 / M3 后 KMS），拒绝任意变量名、文件路径、URL；⑤ 不落盘：值只进本次 fill 参数 |
| **禁止项** | `env://`、`file://`、相对/绝对路径、`..`、`%2e`、`\`、空段、超过两段、从页面内容推断秘密名 |
| **错误处理** | `SECRET_REF_INVALID`（语法/穿越）→ `POLICY_STOP`；`SECRET_NOT_DECLARED`（越权/跨场景）→ `SECRET_ACCESS_DENIED` + `unauthorized-secret-ref` + `POLICY_STOP`；`SECRET_RESOLUTION_FAILED`（后端缺失）→ 拒绝动作 + 安全事件；`secret-rotated` → 标注不伪造 |
| **测试要求** | 合法解析 + 上述 4 类错误各 1 用例；断言 Trace/日志/错误消息中不出现真实值（扫描式断言） |

## 6. Goal Evaluator（🔧 扩展）

**模块**：`packages/agents/goal_assertions.py` + `exploration.evaluate_goal`。

### 6.1 输入

| 参数 | 说明 |
|---|---|
| `intent` | C01（target / expected_outcomes） |
| `goal_definition` | 场景断言列表（现有 **11 种** kind + 新增 **9 种** = v2 共 20 种） |
| `observations` | Observation v2 记录表，**按 `observation_ref` 索引**（不是按数组下标；见 §6.5.2） |
| `bindings` | 动态绑定表（`{unique_suffix}` 等，`dynamic_match` 用） |

### 6.2 输出

`AssertionReport` / `GoalEvaluation`（现状结构）：
`goal_status`（VERIFIED / NOT_VERIFIED / INCONCLUSIVE / NOT_EVALUATED）
+ 逐项 `AssertionResult`（name/kind/verdict/expected/observed/evidence/required/detail）。

> **字段名对齐（DR2.1-06）**：源码 `GoalEvaluation` 的字段名是 **`status`**，不是 `goal_status`。
> 本台账与设计文档中的 `goal_status` 是**语义名**；M1～M3 不重命名源码字段，
> 对外序列化仍是 `status`（C04/C06 与既有读端零影响）。新增的 `test_case_verdict` 是**独立字段**，
> 不得与 `status` 合并成一个字段。

**新增 `test_case_verdict`（DR2-01 / DR2.1-01，与 goal_status 独立）**：

- 取值：`PASSED` / `FAILED` / `INCONCLUSIVE`（**不含 `NOT_EVALUATED`**：用例判定没有"未评估"这一结论）；
- 输入域：GoalStatus **四值**（`VERIFIED` / `NOT_VERIFIED` / `INCONCLUSIVE` / `NOT_EVALUATED`）
  × `expected_goal_status` **二值**（`VERIFIED` / `NOT_VERIFIED`）× `expect_merge`（`PASSED`/`FAILED`/`INCONCLUSIVE`）；
- 来源：路径声明的 `expected_goal_status` + `expect` 独立证据断言求值（**非 Agent 裁决**）；
- **求值优先级（五级，见设计 §3.6.2 唯一权威表）**：

  | 优先级 | 条件 | 结论 |
  |---|---|---|
  | 1 | GoalStatus 明确（`VERIFIED`/`NOT_VERIFIED`）且 ≠ `expected_goal_status` | `FAILED` |
  | 2 | `expect_merge` = `FAILED` | `FAILED` |
  | 3 | GoalStatus ∈ {`INCONCLUSIVE`, `NOT_EVALUATED`} | `INCONCLUSIVE` |
  | 4 | `expect_merge` = `INCONCLUSIVE`（无明确失败但证据不足/缺失） | `INCONCLUSIVE` |
  | 5 | GoalStatus == `expected_goal_status` 且 `expect_merge` = `PASSED` | `PASSED` |

- **`goal_status=NOT_VERIFIED` 不自动等同于 `test_case_verdict=FAILED`**（负向测试可通过）；
- **`NOT_EVALUATED` 不可能产生 `PASSED`**（优先级 3 先拦为 `INCONCLUSIVE`）；
- **`NOT_EVALUATED` 本身也不直接产生 `FAILED`**：优先级 1 的前提是 GoalStatus 已给出明确判定，
  它不进入该比较，因此不构成"预期状态不匹配"；
- **但 required `expect` 有明确 `FAILED` 证据时仍判 `FAILED`**：优先级 2 先于优先级 3，
  与"FAILED 优先于 INCONCLUSIVE"同一条纪律；
- **无明确失败证据时判 `INCONCLUSIVE`**：不可观测绝不自动升级为失败；
- **组合样例**（与设计 §3.6.2 样例 8 同源）：GoalStatus=`NOT_EVALUATED` + `expect_merge`=`FAILED`
  → `test_case_verdict`=`FAILED`（命中优先级 2，**不是** `INCONCLUSIVE`）；
- **FAILED 优先于 INCONCLUSIVE**：明确失败不被别处不可观测稀释；不可观测也绝不自动判失败；
- Compiler 编译准入读 `test_case_verdict`（正常路径 PASSED ⟺ goal VERIFIED，语义不变）。

### 6.3 依赖

Observation v2 采集器；`_path_matches`（单段通配，编译准入共用）。

### 6.4 权限

- **verdict 裁决权唯一归属**：Agent/Planner/模型不得写 verdict；
- 断言只收紧 Compiler 准入，永不放宽；
- 不读输入值（form_state 只报 presence/visibility/disabled）。

### 6.5 错误处理

| 情况 | 行为 |
|---|---|
| 观测不可用 | `INCONCLUSIVE`（永不 FAILED） |
| 断言定义非法 | `AssertionDefinitionError`（加载期拒绝，不进运行期） |
| 绑定缺失（dynamic_match） | `INCONCLUSIVE` |
| 前观测缺失（page_transition） | `INCONCLUSIVE` |
| dom_counts 缺失目标 selector | `INCONCLUSIVE`（不是 count=0） |
| evidence 路径不存在（evidence_complete） | `INCONCLUSIVE` |

### 6.5.1 多步骤目标统一归并规则（DR1-01）

| 优先级 | 条件 | 整体结论 |
|---|---|---|
| 1 | 任一 required 断言 FAILED（任意 stage） | `NOT_VERIFIED` |
| 2 | 无 required FAILED，但存在 required INCONCLUSIVE | `INCONCLUSIVE` |
| 3 | 仅有 optional 断言 | `INCONCLUSIVE` |
| 4 | 所有 required 断言 PASSED | `VERIFIED` |

- `stage: "intermediate"` 失败 = `NOT_VERIFIED`（否决），不是"只记录不否决"；
- `stage: "final"` 与 `intermediate` 归并规则相同；
- `required` 与 `stage` 正交；
- 每步断言通过 `evidence_ref = {observation_ref, field_path}` 定位实际观测
  （**禁止用 `step_index` 推导或数组下标**，见 §6.5.2）；无对应 Observation → 该断言 `INCONCLUSIVE`。

### 6.5.2 Evidence 引用规范（DR2.1-04 唯一权威）

所有断言结论必须能定位到**具体的一条 Observation 记录**，不允许"位置推断"。

**规范形式（唯一允许的写法）**：

```jsonc
// AssertionResult.evidence
{
  "observation_ref": "ob_0007",              // 执行时显式记录的稳定 ID，不随执行顺序重排
  "field_path": "dom_counts.selector:project-item",   // 该 Observation 内的字段路径
  "step_id": "step-2",                       // 该断言所属子目标步骤的稳定标识
  "evidence_ref": "ob_0007#dom_counts.selector:project-item"   // 便于日志/报告引用的串形式
}
```

| 规则 | 内容 |
|---|---|
| E1 | `observation_ref` 在执行时**显式写入**，不由 `step_index` 或列表长度推导（动作步数 ≠ 观察数） |
| E2 | `field_path` 指向该 Observation 记录内的字段（可嵌套），不得跨记录拼接 |
| E3 | 禁止形式：任何以数组下标索引 observation 列表的写法（`step_index` 变量索引、负数索引取倒数第一/二条、字面量索引取第 N 条）。本台账全文不采用下标引用 |
| E4 | 无对应 Observation（引用缺失/ID 不存在）→ 断言结论 `INCONCLUSIVE`（**不允许**绑定"最近一条观察"） |
| E5 | `page_transition` 必须显式声明 `from_ref` / `to_ref`（两个 `observation_ref`），**不得**通过数组位置推断前后观察；`from_ref` 缺失（首条观测）→ `INCONCLUSIVE` |
| E6 | `evidence_complete` 检查的是"`observation_ref` 是否存在且字段非空"，**不是**"该观察是否在数组第 N 位" |
| E7 | 报告/UI 展示证据时，`observation_ref` 必须原样透出，供人工按引用回查 |

**复算一致性**：读取时按 `observation_ref` 取回该条 Observation 记录，重跑求值并与存储结论比对；
引用不可解析 → `goal_assertions_verified=False` + reason `unresolvable-evidence-ref`（不得静默通过）。

### 6.6 测试要求

- 新 kind 逐项参数化（PASSED/FAILED/INCONCLUSIVE 三态）；
- 语义保持 7 条逐条用例（含"VERIFIED 可被断言收紧"）；
- 读取时复算 `goal_assertions_verified` 一致性；
- 回归：`test_goal_semantics.py` / `test_agentic_scenarios.py`（34 项）全过。

### 6.7 版本兼容性

`AssertionResult.to_dict()` 只增字段；旧报告读取不受影响；
`goal_definition` 新 kind 对旧校验器是"未知 kind"——**加载期即拒绝**（定义错误不静默忽略，
与现状 `SUPPORTED_KINDS` 纪律一致），因此场景包必须与运行器同版本部署。

## 7. Trace Recorder（🔧 扩展）

**模块**：`packages/agents/exploration.py`（`ExplorationTrace` / `compute_trace_hash` /
`verify_trace_record`）+ `llm.CallTrace`。

### 7.1 输入

决策链各步记录：observation_ref、Action Proposal、PolicyDecision、execution_result、
goal_evaluation、evidence_refs、token_usage/cost、stop_reason。

### 7.2 输出

- `ExplorationTrace.to_dict()` → 持久化记录（ExplorationStore JSON）；
- `compute_trace_hash` → **v3 哈希**（覆盖 proposal/policy_decision/decision_id/scenario_version）；
- `verify_trace_record` → 布尔 + 版本感知（v1/v2/v3 各自校验）。

### 7.2.1 Trace Hash v3 与历史版本（DR1-06，DR2-09 唯一字段清单）

**DR2-09**：Hash v3 覆盖字段的唯一权威清单见总体设计 §6.3，本表与之保持一致：

| 版本 | 新增覆盖字段（相对前版） | 校验方式 |
|---|---|---|
| v1 | exploration_id, action_sequence, observations, security_events, stop_reason | 按 v1 字段集重算 |
| v2 | + test_intent, agent_decisions, versions(agent/prompt/tool/app/browser) | 按 v2 字段集重算 |
| v3 | + proposed_action, policy_decision, decision_id, decision_source, scenario_id, scenario_version, scenario_digest | 按 v3 字段集重算 |

- 规范化序列化：`json.dumps(payload, ensure_ascii=False, sort_keys=True)` → SHA-256；
- v1/v2 历史记录**不迁移、不改写**，按 `hash_version` 分派校验器；
- `hash_version` 缺失 → 按 v1 校验；
- Hash 提供**完整性校验**（detect tampering），**非真实性认证**（未签名 SHA-256 不能抵御恶意重新计算）。
- **实施阶段归属（R1 明确）**：v3 **只在 M3-7** 实现。M1、M2 阶段 `HASH_VERSION` 保持 2；
  `scenario_id`/`scenario_version`/`scenario_digest` 在此期间照常持久化为普通字段，**不参与哈希**。
  禁止在 M1/M2 把上述三字段并入 v2 字段集——那会让所有既有 v2 记录摘要失配（详见总体设计 §6.3.1）。

### 7.2.2 DecisionContext Snapshot（DR1-06 新增）

每条 DecisionRecord 可携带脱敏后的 `decision_context_snapshot`：
- 含 context_version、intent_summary、observation_summary（计数非原文）、
  budget_remaining、scenario_ref、prompt_template_ref、evidence_refs；
- **不含**密码、输入值、密钥、GT、页面敏感文本原文；
- 与 CallTrace（prompt_sha256）互补，审计人员可追溯决策上下文来源和版本。

### 7.3 依赖

`sanitize_action` / `redact_actions`（脱敏）、hashlib、ExplorationStore。

### 7.4 权限

- 只追加不改写（append-only 纪律）；
- 敏感内容（密码/输入值/prompt 明文）禁止入 Trace（prompt 只存 sha256）；
- GT 不入 Trace。

### 7.5 错误处理

哈希校验失败 → `verify_trace_record=False` + 明确 reason（篡改/截断/版本不符）；
模型失败 → 空决策 + 失败事件入链（不伪造决策）。

### 7.6 测试要求

- 三版本哈希矩阵（v1/v2/v3 记录各自校验通过、跨版本篡改可检出）；
- 决策链关联完整性（decision_id 单链回放）；
- 脱敏断言（trace 无明文密码）；
- Scripted 可重放一致性；Real 复核视图字段齐备（M4）。

### 7.7 版本兼容性

- **v1/v2 历史记录不迁移、不改写**，按 `trace_hash_version` 分派校验器；
- 新字段全部可选；缺失表示"当时没有"，不判篡改；
- C05 零改动（Trace 属探索记录域，不进 C05 事件 Schema）。

- 单次探索费用上限（建议 $0.50）/ 单日费用上限（建议 $20）；
- 并发预算预留 / 失败重试费用计入；
- 实际使用量（响应 `usage`）与估算使用量分开记录；

### A.1 scenario_digest 字段白名单（DR2.1-05，实现唯一清单）

算法规则（编码/排序/分隔符/NaN/浮点/幂等）见设计 §2.2.2；本节只登记**哪些键参与计算**，
实现必须直接引用本表，不得自行增减。

| 类别 | 键（按字母序，实际序列化由 `sort_keys=True` 决定） |
|---|---|
| **参与摘要（28 项语义字段）** | `allowed_actions`、`allowed_origins`、`blocked_reason`、`cleanup`、`constraints`、`data_setup`、`denied_actions`、`description`、`destructive_authorized`、`evidence_requirements`、`goal_definition`、`implemented`、`initial_url`、`intent_templates`、`max_cost_usd`、`max_steps`、`max_tool_calls`、`name`、`paths`、`preconditions`、`scenario_id`、`secret_bindings`、`secret_refs`、`sensitive_selectors`、`stop_conditions`、`success_conditions`、`timeout_budget_s`、`version` |
| **必须排除** | `scenario_digest`（自引用）、`digest_algorithm`、`registered_at`、`loaded_from`、`last_verified_at`、注册表索引键、`run_id`/`trace_id`/观测缓存 |

- 新增字段时**必须**同步本表并升 `version`（否则 digest 变化但版本未升 → 语义漂移）；
- 排除字段**不得**以 null 占位写入载荷；
- 校验：实现层应有单测断言"白名单 == 序列化载荷键集合"（防止漏字段或漏排除）。

### B. Action Proposal（🆕，DR2-03 同步）

```jsonc
{
  "decision_id": "dec_<uuid>",
  "action": "click",
  "arguments": { "selector": "[data-testid=create-submit]" },
  "rationale": "提交创建表单",
  "expected_effect": { "url_path": "/projects", "testid": "success-message" },
  "confidence": 0.82,
  "prompt_version": "planner-v1",
  "model_version": "scripted-not-a-model"     // 或真实模型版本
}

// fill 的敏感输入（DR2-03）：只提交 secret_ref，不提交明文 value
{
  "decision_id": "dec_<uuid>",
  "action": "fill",
  "arguments": { "selector": "[data-testid=password-input]", "secret_ref": "secret://teamflow-login/password" },
  "rationale": "填入密码",
  "expected_effect": { },
  "confidence": 0.9,
  "prompt_version": "planner-v1",
  "model_version": "..."
}
```

Schema 纪律：未知字段拒绝；`action` 枚举校验；`confidence` ∈ [0,1]；
`fill` 参数 `value` 与 `secret_ref` 二选一（敏感输入必须 `secret_ref`）；
Proposal 中不得出现 `test_case_verdict` / `goal_status` 裁决字段（DR2-01）。

## 10. 接口间调用关系（时序摘要）

```
Explorer.explore
  ├─ ScenarioRegistry.require(id, version)        # 锁定场景版本 + scenario_digest
  ├─ Data Setup（数据生命周期适配器，DR2-12）→ 句柄
  ├─ Precondition Evaluator（前置检查，DR2-12）→ precondition_results
  ├─ Budget / ToolSpec 构建（allowed_origins 真实 origin）
  ├─ loop:
  │    PlaywrightAdapter.observe → Observation v2
  │    ContextBuilder.build(...) → DecisionContext（安全上下文不可截断，DR2-08）
  │    Planner.propose(ctx) → ActionProposal | None
  │    PolicyValidator.check(proposal, ...) → PolicyDecision + authorization_token（DR2-02）
  │    ToolGateway.authorize(call, token)         # 验证凭证 6 项（DR2-02）
  │    SecretResolver.resolve(secret_ref)          # 仅 fill 敏感输入（DR2-03）
  │    PlaywrightAdapter.execute
  │    执行后检查 → execution_result
  │    GoalEvaluator.evaluate(...) → goal_status + test_case_verdict（DR2-01）
  │    TraceRecorder.record(全链) → decision_id 链
  └─ finalize: goal_status + test_case_verdict（独立） + stop_reason（独立）
       Cleanup Adapter（清理本 Run 数据，finally 语义，DR2-04）
```

**红线复述**：模型只产生 Proposal（不能裁决 goal_status 也不能裁决 test_case_verdict）；
执行只经 ToolGateway（须持有效授权凭证）；goal_status 只属 Goal Evaluator；
test_case_verdict 只属独立证据断言求值；StopReason ≠ 业务结论；
敏感输入只走 secret_ref；C05 不动；409 不解除。
