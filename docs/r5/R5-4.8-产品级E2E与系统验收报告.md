## 1. 真实 UI User Journey E2E（§5.1）

**新文件**：`tests/e2e/test_user_journey.py`（4 项，全部通过）

夹具：独立 TeamFlow（随机端口）+ 独立平台（随机端口、独立 SQLite、独立 stores），SPA 由平台进程实际托管，Playwright 真实 Chrome 驱动（hash 路由）。

主流程（`test_user_journey_explore_compile_review_run`）严格按规范 1–19 步走 UI，不直接调 API 完成业务动作：

1. 打开 Explorer（hash 路由 `/#/explorer`）
2. 填写完整 TestIntent（intent_ref / goal / expected_outcomes / target / base_url，全部经 `data-testid` 定位）
3. 发起探索 → 等待 `goal-status=VERIFIED`
4. 轨迹页展示执行状态 / 停止原因 / 目标验证三轴
5. 目标验证结论可见
6. 点击「编译为候选」→ 生成候选提示
7. 前往审核队列 → 打开候选详情
8. 校验审核依据真实渲染：goal、target `/projects`、value_ref（teamflow.password）、步骤 ≥4、Oracle 列表
9. 审核清单 ≥3 项且初始未勾选；**批准按钮锁定**
10. 逐项勾选清单 + 不确定项确认
11. 填写评审人 + 审批记录 → 批准 → 晋升提示
12. 打开正式 TestCase（TC-CAND-*）→ 步骤与 Oracle 绑定页
13. 发起 FullChain（真实浏览器全链）→ 全链结果 PASSED
14–15. 查看 Run 详情
16–19. 证据台账 / 证据图谱页可达

负向场景：

- `test_negative_scenario_without_goal_cannot_compile`：无 goal/target 的探索 → UI 显示 `NOT_EVALUATED`，编译按钮禁用；同时用 API 直接对同一无目标探索调用 compile → **409**（服务端强制，与 UI 一致）。
- `test_unsupported_scenario_is_rejected_by_the_api`：未注册场景 → 422 `UNSUPPORTED_SCENARIO`。
- `test_state_after_the_journey_is_persisted`：journey 结束后候选 APPROVED、正式用例存在、chain completed。
