## 4. 修订前问题 → 修订后统一设计

### DR1-01：多步骤目标语义

**修订前（三种矛盾表述）**：
1. §3.3 row 7："中间步失败即整体失败"
2. §3.3 row 8："intermediate 失败只记录不否决（对齐 optional 语义）"
3. §3.5："intermediate 失败→记录并在 goal_evaluation 标注断点，整体不 VERIFIED"

**修订后（统一归并规则）**：

| 优先级 | 条件 | 整体结论 |
|---|---|---|
| 1 | 任一 required 断言 FAILED（任意 stage） | `NOT_VERIFIED` |
| 2 | 无 required FAILED，但存在 required INCONCLUSIVE | `INCONCLUSIVE` |
| 3 | 仅有 optional 断言 | `INCONCLUSIVE` |
| 4 | 所有 required 断言 PASSED | `VERIFIED` |

- `stage: "intermediate"` 失败 = NOT_VERIFIED（**否决**），不是"只记录不否决"
- `final_state`/`intermediate_state` 独立 kind **取消**，语义由 `multi_step_goal.stage` 覆盖
- `required` 与 `stage` 正交
- 合法/非法样例：见总体设计 §3.4

### DR1-02：Scenario Package 版本化 API

| 修订前 | 修订后 |
|---|---|
| 无版本概念 | `(scenario_id, version)` 唯一索引，SemVer |
| API 无 scenario_version | `RunExplorationRequest.scenario_version: str = ""`（可选，向后兼容） |
| public_view 只有 id→description | 保留旧格式 + 新增 `scenario_versions` 增量字段 |
| Trace 无版本记录 | Trace 必须记录真实执行版本，Hash v3 覆盖 |
| 不存在版本无明确错误 | `UNSUPPORTED_SCENARIO_VERSION` + `available_versions` |
| 历史记录无版本 | 视为 `1.x` 历史，按 scenario_id 匹配最低已实现版本复算 |

### DR1-03：TeamFlow 数据生命周期

| 修订前 | 修订后 |
|---|---|
| project-edit 声称需全部新建后端 | **复用已有 `service.update_project()` + `PUT` API**，仅增加 Web 编辑页面 + 表单路由 |
| form-validation 声称"走已有 API（项目创建/删除）" | **修正**：无 DELETE API；采用**方案 B（测试 Fixture/数据生命周期适配器）** |
| "若删除接口缺失则记 BLOCKED" | 方案 B 不需要 DELETE API，适配器通过 DB session 清理 |
| 无数据所有权/失败语义/并发隔离 | 明确 8 项：run_id 唯一后缀、所有权、创建/清理失败语义、崩溃恢复、并发隔离 |

**方案选择理由**：方案 B（测试 Fixture）比方案 A（新增隔离清理接口）风险更低、最容易验证：
- 不改 SUT API 面
- 不暴露远程清理接口
- DB session 直接操作仅限测试环境
- 禁止通过 `reset_data()` 清空正式数据库

### DR1-04：PolicyValidator 与 ToolGateway

| 修订前 | 修订后 |
|---|---|
| 职责边界模糊 | **明确分离**：PolicyValidator=策略层；ToolGateway=安全层（唯一执行授权入口） |
| 无 fail-closed | 检查异常 → 拒绝放行，探索以 ERROR 停止 |
| 无重复拒绝限制 | 连续 2 次同参数拒绝 → POLICY_STOP；累计 5 次 → POLICY_STOP |
| 无最大重规划 | 单步 2 次重规划；全局 max_steps×50% |
| 无危险操作分类 | 4 类：越界导航/高频写/破坏性/重复操作 |
| 无合法重试区分 | 比较脱敏后 args，不同=合法重试，相同=重复危险 |
| 页面不可信未强调 | 两层校验都不从页面内容提取权限/预算 |

### DR1-05：Observation v2 契约

新增 §3.2.1 完整采集契约（11 项）：
1. dom_counts selector 白名单 + 计数上限（≤200/selector，≤20 条目）
2. dom_relations 数据结构（`{kind, left, right, observed}`，≤10 条）
3. element_attr 属性白名单（role/aria-label/href路径/data-*/type/name/placeholder）
4. href URL 脱敏（仅路径部分，去 query/hash）
5. 不采集输入值（红线不变）
6. Observation 体积上限（总 ≤32KB，各字段分项）
7. 单次页面采集超时（≤5000ms）
8. table_row_count/list_item_count 统一比较规则（eq/gte/lte，空列表=0 可观测）
9. dynamic_match 绑定来源（运行时绑定表/场景声明 bindings，缺失→INCONCLUSIVE）
10. page_transition 历史观测要求（需前观测，首步→INCONCLUSIVE）
11. evidence_complete 独立校验（不依赖其他断言结果，无循环依赖）

每种新断言含：JSON Schema、合法样例、非法样例、PASSED/FAILED/INCONCLUSIVE、Evidence 路径、读取时复算规则。

### DR1-06：Trace Hash v3 与上下文审计

| 修订前 | 修订后 |
|---|---|
| v3 未定义具体覆盖字段 | v3 = v2 + proposed_action, policy_decision, decision_id, scenario_version, decision_source |
| 无 DecisionContext Snapshot | 新增 `decision_context_snapshot`（脱敏上下文快照：intent_summary/observation_summary/budget/scenario_ref/prompt_template_ref/evidence_refs） |

| 历史版本处理未明确 | v1/v2 不迁移不改写，按 hash_version 分派校验器 |

**红线**：Snapshot 不含密码、输入值、密钥、GT、页面敏感文本原文。
